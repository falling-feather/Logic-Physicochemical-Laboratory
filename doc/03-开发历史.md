### 1.2 V7.4.23 裁剪三角色资源加载

- **提交日期**：2026-07-16
- **任务编号**：`FE-006`
- **提交标题**：`V7.4.23 裁剪三角色资源加载`
- **问题来源**：V7.4.0 已在 Router 前确认会话并隐藏越权导航/section，Router 也会在页面脚本加载前做角色守卫；但 `index.html` 仍静态加载三端 CSS，APP_SHELL 和 HTTP fallback 仍无条件包含 admin/teacher/student CSS/JS。旧实现只能证明“不呈现/不执行越权页面”，不能证明未授权角色资源没有被请求或进入共享缓存。

### 1.3 V7.4.22 硬化认证双通道契约

- **提交日期**：2026-07-15
- **任务编号**：`BE-002`
- **提交标题**：`V7.4.22 硬化认证双通道契约`
- **问题来源**：浏览器统一 API client 已采用 HttpOnly Cookie-only，但 FastAPI 依赖仍让 Bearer 静默覆盖 Cookie；测试客户端登录后自动保留 Cookie，既有 Bearer helper 又叠加 Authorization，使测试实际依赖这一覆盖顺序。Starlette 对重复同名会话 Cookie 还会静默保留最后一个值，存在凭据歧义和 Cookie tossing 残余风险。
- **具体完成**：认证依赖改为单请求单通道：Cookie-only 与显式 Bearer-only 保持可用；Cookie+Bearer、重复同名会话 Cookie（同一头或分离头）、重复 Authorization 和畸形 Authorization 在 token 哈希与数据库查询前用稳定脱敏错误 fail closed。所有非浏览器 Bearer 测试 helper 显式发送空 Cookie，避免 TestClient cookie jar 伪造兼容证据。
- **兼容与 OpenAPI**：登录响应继续返回 `access_token` 以兼容非浏览器 API 客户端；Pydantic/OpenAPI 描述和后端 README 明确浏览器必须忽略、不得存储或回传。兼容 token 仍出现在登录 JSON 中是已接受的阶段性残余风险；未来拆分浏览器登录与 token 颁发必须独立规划，不能在本版破坏调用方。
- **独立审查**：SEC 只读审查确认 Cookie-only、Bearer-only、混合/畸形拒绝和静态错误脱敏正确，并发现重复 Cookie 与重复 Authorization 测试缺口；主开发补齐原始 Cookie 头计数和正反向测试后复验通过。
- **验证证据**：认证专项 43 项通过；目标发布门禁 5 项在沙箱外通过；冻结代码的后端全量 397 项收集、392 通过、5 跳过、0 失败；`git diff --check`、文档兼容与项目对接门禁通过。本机 FastAPI 0.136.3/Starlette 1.1.0 与锁文件 Starlette 1.3.1 存在差异，锁定依赖环境/CI 复验仍保留为交付证据边界。
- **后续任务**：按 09 进入 `FE-006/V7.4.23` 三角色资源级裁剪；不得把角色 hidden/执行守卫误报为未授权资源未下载或未缓存。
