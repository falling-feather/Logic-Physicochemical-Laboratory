# 工科实验室 · Windows 云服务器部署文档

## 一、环境要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Windows 10 / Windows Server 2016+ |
| 软件依赖 | **Git**、**CMake ≥ 3.14**、**Visual Studio Build Tools**（或 MinGW-w64）；启用 Python API 时还需要 **Python 3.11+**、后端依赖和 MySQL |
| 网络 | 公网 IP，开放 **910** 端口（TCP 入站） |
| 磁盘空间 | ≥ 500 MB（源码 + VS 编译产物 + 依赖） |

### 依赖下载地址

| 软件 | 下载地址 |
|------|---------|
| Git for Windows | https://git-scm.com/download/win |
| CMake | https://cmake.org/download/ （安装时勾选"添加到 PATH"） |
| Visual Studio Build Tools | https://visualstudio.microsoft.com/visual-cpp-build-tools/ （选择"使用 C++ 的桌面开发"工作负载） |

> **验证安装**：打开 PowerShell，分别运行 `git --version`、`cmake --version` 确认可用。

## 二、服务架构

> v6.5 后端化已在 `houduan` 分支新增 `backend/` FastAPI 业务后端。当前推荐采用“静态站继续由 C++ 服务承载、`/api/*` 转发到 Python API”的渐进共存模式；若 Python API 出现故障，可立即回滚到纯静态/C++ 服务路径。

```
用户浏览器
  └──▶  反向代理 :80/:443
        ├── /            ──▶ englab_server.exe :910  静态文件、历史健康检查
        └── /api/*       ──▶ uvicorn FastAPI :8000   登录、课程、管理端、内容协议
```

- C++ 服务继续提供静态页面和历史占位 API，保证旧路径可回滚。
- Python API 只承担新增业务接口，所有 `/api/*` 响应默认 `Cache-Control: no-store`，避免 Service Worker 或中间层缓存业务 JSON。
- 反向代理应透传 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto` 和 `X-Request-ID`；未传 `X-Request-ID` 时 FastAPI 会生成并回传。
- 两个进程均可用 NSSM 或同等级进程管理器注册为 Windows 服务，日志分开写入。

## 三、一键部署（推荐）

### 步骤

1. 安装好上述依赖软件（Git、CMake、VS Build Tools）
2. **以管理员身份**打开 PowerShell
3. 如果首次运行脚本，先放行执行策略：
   ```powershell
   Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
   ```
4. 执行部署脚本：
   ```powershell
   # 方式 A：先克隆再运行
   git clone https://github.com/falling-feather/Logic-Physicochemical-Laboratory.git C:\englab
   cd C:\englab
   .\deploy.ps1

   # 方式 B：自定义参数
   .\deploy.ps1 -Port 910 -InstallDir "D:\englab"
   ```

脚本自动完成：检查依赖 → 克隆/更新代码 → 编译 → 防火墙放行 → 下载 NSSM → 注册 Windows 服务 → 启动 → 健康检查。

## 四、手动部署步骤

### 4.1 克隆项目

```powershell
git clone https://github.com/falling-feather/Logic-Physicochemical-Laboratory.git C:\englab
```

### 4.2 编译服务器

**以管理员 PowerShell 或"Developer Command Prompt for VS"执行：**

```powershell
cd C:\englab\server

# Visual Studio (自动检测版本)
cmake -B build -S . -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release

# 编译产物
# VS: C:\englab\server\build\Release\englab_server.exe
# MinGW: C:\englab\server\build\englab_server.exe
```

### 4.3 测试运行

```powershell
cd C:\englab
.\server\build\Release\englab_server.exe -p 910 -r C:\englab
# 浏览器访问 http://localhost:910 确认正常
# Ctrl+C 停止
```

### 4.4 防火墙放行

```powershell
New-NetFirewallRule -DisplayName "EngLab Server (Port 910)" `
    -Direction Inbound -Protocol TCP -LocalPort 910 `
    -Action Allow -Profile Any
```

### 4.5 注册 Windows 服务

推荐使用 [NSSM](https://nssm.cc/)（Non-Sucking Service Manager）：

```powershell
# 下载 NSSM
Invoke-WebRequest -Uri "https://nssm.cc/release/nssm-2.24.zip" -OutFile nssm.zip
Expand-Archive nssm.zip -DestinationPath C:\englab\tools
Copy-Item C:\englab\tools\nssm-2.24\win64\nssm.exe C:\englab\tools\nssm.exe

# 注册服务
C:\englab\tools\nssm.exe install EngLab "C:\englab\server\build\Release\englab_server.exe" "-p 910 -r C:\englab"
C:\englab\tools\nssm.exe set EngLab AppDirectory C:\englab
C:\englab\tools\nssm.exe set EngLab Description "EngLab Interactive Science Platform"
C:\englab\tools\nssm.exe set EngLab Start SERVICE_AUTO_START
C:\englab\tools\nssm.exe set EngLab AppStdout C:\englab\logs\stdout.log
C:\englab\tools\nssm.exe set EngLab AppStderr C:\englab\logs\stderr.log
New-Item -ItemType Directory -Path C:\englab\logs -Force

# 启动
Start-Service EngLab
```

## 六、Python API 并存部署（v6.5）

### 6.1 后端环境

```powershell
cd C:\englab\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

生产环境至少配置：

```powershell
$env:ASTRA_ENVIRONMENT='production'
$env:ASTRA_DATABASE_URL='mysql+pymysql://astra:***@127.0.0.1:3306/astra?charset=utf8mb4'
$env:ASTRA_ADMIN_BOOTSTRAP_TOKEN='<strong-random-token>'
$env:ASTRA_AUDIT_IP_HASH_SALT='<strong-random-salt>'
$env:ASTRA_CORS_ORIGINS='https://your-domain.example'
```

知识快照日/周调度器默认关闭。若本机只运行单个 `AstraApi` 进程、单个 uvicorn worker，且已完成迁移与预检，可按需启用：

```powershell
$env:ASTRA_KNOWLEDGE_SNAPSHOT_SCHEDULER_ENABLED='true'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_SCHEDULER_RUN_ON_START='false'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_SCHEDULER_INTERVAL_SECONDS='300'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_DAILY_ENABLED='true'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_DAILY_HOUR='3'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_WEEKLY_ENABLED='true'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_WEEKLY_WEEKDAY='0'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_WEEKLY_HOUR='4'
$env:ASTRA_KNOWLEDGE_SNAPSHOT_RETRY_ATTEMPTS='3'
```

当前调度器是 FastAPI lifespan 内的进程内任务，适合作为首轮服务注册基础；多 worker、多副本、跨机器部署前需要补数据库锁、leader election 或外部任务队列，避免同一窗口重复重算。

### 6.2 迁移与预检

```powershell
cd C:\englab\backend
.\.venv\Scripts\Activate.ps1
python -m alembic upgrade head
python -m scripts.deploy_preflight
python -m scripts.deploy_smoke --require-mysql
```

`deploy_preflight` 会输出 JSON，并在数据库不可连或 Alembic 当前版本不是 head 时返回非零退出码。`deploy_smoke --require-mysql` 会在预检基础上继续检查模型期望表集合、MySQL 方言和 `/api/health` 运行态结果；生产上线前必须通过这两个脚本。真实 MySQL 的账号权限、字符集、时区和备份仍需在环境侧确认。

`20260706_0022` 会为 `users` 与 `login_attempts` 增加 normalized username 唯一约束。迁移前应先按 `lower(trim(username))` 扫描 `users`，若存在大小写或首尾空白归一后重复的账号，迁移会明确失败并要求人工清洗；`login_attempts` 只是登录失败临时桶，迁移会清空重复或空白 normalized bucket 后重建唯一约束。上线窗口内建议先备份，再执行 Alembic 迁移、预检和 smoke。

如需显式指定目标库：

```powershell
python -m scripts.deploy_smoke --database-url "mysql+pymysql://astra:******@127.0.0.1:3306/astra?charset=utf8mb4" --require-mysql
```

该 smoke 使用当前代码在进程内启动 FastAPI 检查 API 与数据库配置，运行时会临时关闭自动建表和知识快照调度器，只验证迁移后的现有状态；它不替代后续 Windows 服务、反向代理和公网访问验证。

### 6.3 正式内容初始化

正式环境 `ASTRA_AUTO_CREATE_TABLES=false` 时不会随 FastAPI 启动自动 seed 内容页。迁移、预检、部署 smoke 和首个 admin 初始化完成后，先 dry-run 再正式写入：

```powershell
cd C:\englab\backend
.\.venv\Scripts\Activate.ps1
python -m scripts.init_content_pages --dry-run --publisher-user-id <admin_id>
python -m scripts.init_content_pages --publisher-user-id <admin_id> --allow-reviewed-scripts
```

初始化脚本默认先复用部署预检，随后为内置页面写入或修复 `content_pages` 与 `content_page_versions`，并输出 JSON 报告。生产环境建议显式传入 active admin 的 `--publisher-user-id` 作为发布归因；若不传，脚本会选择第一个 active admin。内置页面包含脚本引用，非 dry-run 必须使用 `--allow-reviewed-scripts` 表示已完成人工审核。

若已有同 slug 当前版本与内置 schema 不同，脚本默认报告冲突并不覆盖；确认需要推进内置 schema 时，使用 `--upgrade-existing` 追加新版本并保留 `previous_version_id`。存在活跃草稿时升级默认阻断，只有明确接受这些草稿需要重新基于新版本处理时才加 `--allow-stale-drafts`。`--skip-preflight` 仅用于受控测试或恢复，不作为常规上线步骤。

### 6.4 启动 FastAPI

本地验证：

```powershell
cd C:\englab\backend
.\.venv\Scripts\Activate.ps1
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

NSSM 服务示例：

```powershell
C:\englab\tools\nssm.exe install AstraApi "C:\englab\backend\.venv\Scripts\python.exe" "-m uvicorn app.main:app --host 127.0.0.1 --port 8000"
C:\englab\tools\nssm.exe set AstraApi AppDirectory C:\englab\backend
C:\englab\tools\nssm.exe set AstraApi Description "Astra FastAPI Business API"
C:\englab\tools\nssm.exe set AstraApi Start SERVICE_AUTO_START
C:\englab\tools\nssm.exe set AstraApi AppStdout C:\englab\logs\astra-api-stdout.log
C:\englab\tools\nssm.exe set AstraApi AppStderr C:\englab\logs\astra-api-stderr.log
Start-Service AstraApi
```

若启用知识快照调度器，保持单 worker 启动；不要在同一数据库上同时开启多个 `AstraApi` 调度器实例。

### 6.5 反向代理分流

示例策略：

```text
/api/*  -> http://127.0.0.1:8000/api/*
/*      -> http://127.0.0.1:910/*
```

代理要求：

- `/api/*` 不做静态缓存，不改写 `Cache-Control: no-store`。
- 透传 `X-Request-ID`；没有上游 request id 时，可由代理生成，也可交给 FastAPI 生成。
- 只信任来自反向代理的 `X-Forwarded-For`，不要把 FastAPI 直接暴露到公网。
- 静态资源仍可按原 Service Worker 与静态缓存策略运行，业务 JSON 只走 Python API 的 no-store 响应。

## 七、回滚路径

| 场景 | 回滚动作 | 验证 |
| ---- | -------- | ---- |
| Python API 启动失败 | 反向代理暂时移除 `/api/* -> :8000` 分流，保留 C++ 静态站；停止 `AstraApi` 服务 | 首页可访问；`http://localhost:910/api/health` 可用 |
| 数据库迁移失败 | 不启动新 API；保留旧 API 服务和旧数据库；从备份恢复后再重跑迁移 | `python -m scripts.deploy_preflight` 和 `python -m scripts.deploy_smoke --require-mysql` 通过 |
| 新版本 API 业务异常 | 切回上一版代码目录或上一提交，重启 `AstraApi`；数据库结构已前向迁移时，不执行破坏性降级，优先用兼容代码修复 | `/api/health`、登录、管理端审计查询通过 |
| 静态站异常 | 回滚 C++ 构建产物或上一版静态资源，Python API 可继续保留 | 首页、试点 `backendSchema=1` 页面可访问 |

上线前应保留：

- 当前代码提交 hash、上一版代码目录或压缩包。
- MySQL 备份和 Alembic 当前 revision。
- `EngLab` 与 `AstraApi` 两个服务的日志路径。
- 反向代理配置备份。

## 八、云服务器安全组

除了 Windows 防火墙，还需在云厂商控制台（阿里云/腾讯云/华为云等）的**安全组**中放行：

| 方向 | 协议 | 端口 | 来源 |
|------|------|------|------|
| 入站 | TCP | 910 | 0.0.0.0/0 |
| 入站 | TCP | 80 / 443 | 0.0.0.0/0（使用反向代理时） |

> ⚠️ 这一步很容易遗漏，如果 Windows 防火墙已放行但外网仍无法访问，请检查安全组设置。
>
> FastAPI 的 `8000` 建议只监听 `127.0.0.1`，不直接对公网开放。

## 九、故障排查

| 症状 | 排查方法 |
|------|---------|
| 外网无法访问 | ① 检查安全组是否放行 910 ② `Test-NetConnection localhost -Port 910` ③ `netstat -ano \| findstr 910` |
| 服务启动失败 | 查看 `C:\englab\logs\stderr.log`；尝试手动运行 `.\englab_server.exe -p 910 -r C:\englab` 观察报错 |
| 编译失败 (cmake) | 确认已安装 VS Build Tools 的 "C++ 桌面开发" 工作负载；确认 cmake 在 PATH |
| 页面白屏 | `Invoke-RestMethod http://localhost:910/` 检查是否返回 HTML，确认 `-r` 路径正确 |
| 端口被占用 | `netstat -ano \| findstr :910` 找到 PID 后 `taskkill /PID <PID> /F` |
| Python API degraded | `Invoke-RestMethod http://127.0.0.1:8000/api/health`，再查看 `astra-api-stderr.log` 和数据库连接 |
| 预检失败 | 查看 `python -m scripts.deploy_preflight` 输出的 `database` / `migrations` 字段；先修数据库连通，再修 Alembic revision |
| 部署 smoke 失败 | 查看 `python -m scripts.deploy_smoke --require-mysql` 输出的 `preflight` / `schema` / `api` 字段；先确认 MySQL 方言、缺失表和 `/api/health` 数据库状态 |
| API 被缓存 | 检查代理是否保留 `Cache-Control: no-store`，确认请求命中的是 `/api/* -> :8000` |
