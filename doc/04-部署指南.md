## 本机验收入口（非目标发布）

Windows 用户可从仓库根目录用一条命令启动完整本机站点：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1
```

默认行为如下：

1. 只接受 Python 3.12+，在仓库内创建/复用被 Git 忽略的 `.venv`；依赖严格从 `backend/requirements.lock` 使用 `--require-hashes` 安装，锁文件 SHA 变化时才重装。
2. 数据目录默认为 `%LOCALAPPDATA%\Astra\local-preview`，其中保存 `astra-local.sqlite3` 与随机审计盐；可用 `-DataDirectory <绝对或相对路径>` 指向隔离验收目录。
3. 每次启动先执行 Alembic `upgrade head`，再以前台方式运行 `app.local_preview:app`，只绑定 `127.0.0.1:9001`。浏览器统一访问 `http://127.0.0.1:9001/`，无需另启静态站或 API。
4. `app.local_preview` 复用权威 FastAPI `create_app()`，只公开 `index.html`、`sw.js`、`LICENSE.md`、`pages/`、`shared/`、`UI/` 与 `codevis/`；`backend/`、`doc/`、`server/`、`.git/`、`deploy.ps1`、lockfile 和路径穿越保持 404。V7.5.8 起显式注册 `.webp -> image/webp`，不得让 Windows 主机差异导致未来星系主视觉返回通用二进制 MIME。
5. 规范化数据目录 SHA-256 同时绑定命名互斥量和实例响应头，同一 SQLite 即使指定不同端口也不能并发启动，不同数据目录也不会被误认成当前实例。端口已运行同一星序本机站时脚本返回成功并打印地址；其他进程、API-only 实例或不同数据库占用时失败，不会误杀进程或改用另一端口。本机首页会移除旧式 `apiBase` 查询、清除同 origin 旧 API base，并令 API client 拒绝所有跨 origin 地址，保证验收会话继续使用当前端口同源 `/api`。用 `Ctrl+C` 停止前台 Uvicorn，停止后端口释放且不保留子进程。
6. 启动脚本把审核白名单复制到仓库外运行快照后再提供静态文件，因此正在运行的实例不会热读取工作树。源码或静态资源更新后，应正常停止并重启 `astra-local.ps1`；不要把“旧实例仍返回旧资产”误判为浏览器缓存问题，也不要手工改运行快照。

需要创建首个本机管理员时，在尚无管理员的隔离数据库上执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1 -BootstrapAdmin
```

用户名、显示名和密码通过交互读取；密码使用 `SecureString` 隐藏输入，只在当前进程内转换后经 UTF-8 stdin 传给 `scripts.local_preview_bootstrap_admin`，再调用现有 `/api/admin/bootstrap`。脚本仅为该调用短暂启用 bootstrap，完成后立即关闭；不接受命令行密码、不写凭据文件、不在输出中回显密码，已有管理员时返回 `already-complete`。

QA-009 的本机三角色证明复用启动时预置账号，不为自动化重新打开运行时 bootstrap。证明进程只在 `--confirm-isolated-environment` 下接受成对的 `ASTRA_QA_ADMIN_USERNAME`/`ASTRA_QA_ADMIN_PASSWORD`，缺一即失败；凭据只用于登录且不写入 JSON 报告。两项变量应在 Node 进程结束后立即清除，输出必须指向仓库外的全新空目录。`--confirm-target-staging` 继续只接受 `ASTRA_ADMIN_BOOTSTRAP_TOKEN` 和冻结目标环境，不读取本机管理员变量。

bootstrap 状态必须按数据库阶段解释：全新未预置且运行时开关关闭时，直接请求返回 403；`-BootstrapAdmin` 成功创建首管理员后，重复请求返回 409 `Admin bootstrap is already complete`。两种结果都必须是非 201、不得新增管理员或审计写入。V7.4.35 的 QA-009 独立报告为 `ok=true`、`adminProvisioning=pre-provisioned-local-environment`、12/12 目标语义通过；结束后凭据变量已清除，9001 已停止。

此入口固定为 development + SQLite，本轮优先保证本机可用性。它不会生成 TLS、域名、Windows 服务、正式 MySQL、备份/恢复、监控或七类 evidence，也不调用或修改 `deploy.ps1`。因此不得把 9001 health、浏览器截图或本机数据库外推为 R6、staging 或 production 证据；目标发布仍按下文 51/51 总闸执行。

## 〇、目标环境发布证据闸

V7.4.28 起，目标 staging/production 使用 `target-release-v2`，不再接受 V7.3.2 的“文件 hash + manifest 自选状态字段”口径。先复制 [`backend/target-release-manifest.example.json`](../backend/target-release-manifest.example.json) 到独立证据包目录，并以 [`backend/release-artifact-manifest.example.json`](../backend/release-artifact-manifest.example.json) 生成同包制品清单，替换全部 `REPLACE_*`。目标必须同时填写 environment、公开 DNS且标准 443 的精确 HTTPS origin 与目标实例 ID；IP、单标签、保留/示例域、非法 DNS label、路径/query/fragment 和非标准端口会在 seal、51 项总闸及服务包生成三个入口一致拒绝。release 必须填写 `Vx.y.z`、40 位冻结 Git revision、制品清单相对路径、该清单文件的 SHA-256 和本次 evidence bundle ID。清单必须以 `release-artifact-manifest-v1` 绑定同一 version/revision，并至少逐项记录 static/API/worker/proxy/migrations 五类不可变制品引用、SHA-256 与正数大小；清单和真实制品继续进入组织受控归档/变更单。

四份自动报告先原样输出到 `raw/`；数据库恢复与运行时回滚只能从 fail-closed 模板开始填写，模板本身 `ok=false`，不能作为证据。`target_browser_smoke` 模板仅保留为 schema 反例/参考；V7.4.29 起，真实目标浏览器 raw 必须由 `role-workflows-proof.cjs --confirm-target-staging` 在成功运行后直接生成，不得人工把模板改成 ready：

```powershell
cd backend
python -m scripts.target_release_evidence template --evidence-id database_restore --output C:\release-evidence\raw\database-restore.json
python -m scripts.target_release_evidence template --evidence-id runtime_rollback --output C:\release-evidence\raw\runtime-rollback.json
```

每份 raw 报告完成后必须用唯一 run ID 封装。四份自动报告自身必须携带执行时写入的 `generated_at`，不能用重新封装刷新旧报告；封装器先复核同包制品清单，再按 evidence 类型验证固定语义和 raw 时间，最后把目标实例、origin、版本、revision、制品清单路径/SHA、bundle ID 与七天内封装时间写入 envelope。不通过的 raw 报告不会生成 evidence：

```powershell
python -m scripts.target_release_evidence seal `
  --manifest C:\release-evidence\target-release.json `
  --evidence-id deploy_preflight `
  --run-id preflight-CHG-2026-0716-01 `
  --input C:\release-evidence\raw\deploy-preflight.json `
  --output C:\release-evidence\evidence\deploy-preflight.json
```

对七类报告逐一封装，把命令返回的 SHA-256 和 run ID写回 manifest，再运行总闸：

```powershell
cd backend
python -m scripts.target_release_gate --manifest C:\release-evidence\target-release.json
```

发布闸默认失败，只有 51 项全部通过才返回 `ok=true / status=ready / decision=通过`。它要求：

1. 目标必须是 `staging` 或 `production`，使用已替换、非本地/非示例的 HTTPS origin 和唯一实例 ID，并有 30 天内的运维 owner、变更单和审批时间；`learn.example.edu`、`.example/.test/.invalid` 及 `REPLACE_*` 一律失败。
2. release version、冻结 commit、同包制品清单路径/SHA-256 与 bundle ID 必须齐全；清单 version/revision 和五类制品条目必须通过。manifest 只能包含精确七类 evidence；它们必须使用互不重复的 run ID，并与同一 target/release/bundle 完全一致，禁止添加自定义“自批”项或跨环境/跨提交拼装。
3. TLS 至少 1.2、HSTS 已启用、证书剩余至少 14 天；公网端口只能是 80/443，内层 static/API/proxy 端口有异机不可达证据。manifest 必须冻结 `public_probe_host` 和外部执行证据引用；目标 topology 必须显式启用 `--require-public-port-isolation`、传入同一 `--external-probe-ref` 并启用 `--verify-windows-services`。省略公网原始 API URL/外部引用、目标无法解析到真实公网地址或 SCM 回读缺项都会失败，API 探测端口还必须出现在 manifest 的 blocked inner ports 中。
4. secret 只写 provider 与三个以上互不重复的不透明引用；引用不得是 URL、赋值串或常见明文 token。manifest 或 evidence 正文出现 password/token/credential/private key/DSN/数据库 URL、带 userinfo 的 URL或任何“敏感值已返回”标记会直接阻断，总闸不回显命中值。
5. 正式 MySQL 使用独立服务账号并有最小权限复核；preflight 必须来自同一 environment、显式 require MySQL、关闭自动建表、字符集通过且 current=head=0050。deploy smoke 还必须确认 0047 的学校/班级治理列、0048 的稳定课程/活动键和发布计划表、0049 的四类 OJ 表以及 0050 的过期租约恢复索引均存在，API health 命中 `astra-backend`。
6. 备份至少保留 7 天、带 SHA-256，并在不同数据库完成 30 天内恢复演练；runtime rollback 必须绑定候选/上一 revision、三类回滚引用、四服务和七项恢复 smoke。target browser smoke 必须绑定本次 40 位 release revision，并覆盖 student/teacher/admin、桌面/390×844、登录前置、Cookie、角色导航/资源隔离、Service Worker no-store、越权拒绝、组织陈旧版本 409、组织归档/恢复与浏览器错误/溢出扫描。
7. `backend_stage_gate` 必须是未使用时间覆盖的 `V6.6.63` 只读精确 15/15，15 个 gate 均为 passed 且无敏感值；七份 envelope 必须在 manifest 目录内、SHA-256 匹配、封装时间不早于七天，自动 raw 执行时间和目标浏览器完成时间还必须同时落在封装时刻与总闸当前时刻的有效窗口内。路径穿越、匿名/自定义额外项、重复 ID、重复 run ID、`status_path/expected` 覆盖、文件过大、空壳 `{"ok":true}` 或语义缺项均失败。

`target_release_gate` 与 `target_release_evidence seal` 的正式 CLI 不接受任何 `--now`/测试时间覆盖；自动化测试只能直接调用可注入时钟的内部函数。示例 manifest、制品清单和人工模板只展示结构，不是可提交证据；禁止把 secret、真实 DSN、备份内容或真实证据包放进仓库。完整证据包应进入组织受控归档或变更单附件，仓库只保留无敏感信息的模板、验证代码和发布历史结论。

## 二、服务架构

> 当前采用“静态站由 C++ 服务承载、`/api/*` 转发到 FastAPI”的四服务共存模式；若 Python API 出现故障，静态学习内容保持可用，但三端实时数据必须明确显示不可用，不能回退为伪实时数据。

```
用户浏览器
  └──▶  反向代理 :80/:443
        ├── /            ──▶ englab_server.exe :910  静态文件、历史健康检查
        └── /api/*       ──▶ uvicorn FastAPI :8000   登录、课程、管理端、内容协议
```

- C++ 服务继续提供静态页面和内部存活探针，保证静态路径可回滚；不再提供历史业务形态占位 API。
- Python API 只承担新增业务接口，所有 `/api/*` 响应默认 `Cache-Control: no-store`，避免 Service Worker 或中间层缓存业务 JSON。
- 反向代理应透传 `Host`、`X-Forwarded-For`、`X-Forwarded-Proto` 和 `X-Request-ID`；未传 `X-Request-ID` 时 FastAPI 会生成并回传。FastAPI 审计 IP 哈希默认不信任 `X-Forwarded-For`，生产若需使用真实客户端 IP，应同时配置 `ASTRA_AUDIT_TRUST_FORWARDED_FOR=true` 和可信代理来源 `ASTRA_AUDIT_TRUSTED_PROXY_HOSTS`。
- 推荐将 C++、FastAPI、独立 worker 和 Caddy 分别注册为 `EngLab/AstraApi/AstraWorker/AstraProxy` 四个 WinSW 服务，日志分开写入；代理不得对 API/静态上游建立 SCM 硬依赖，否则停止 API 会破坏静态回退。

## 三、受控服务包生成（推荐）

生产部署不再提供“下载工具 + 开端口 + 安装服务”的一键脚本。先从官方来源分别取得 WinSW/Caddy，按发布方 checksum 或组织制品清单复核，再准备合格的 Release C++ 构建产物；不得让部署脚本在高权限上下文中临时下载未校验可执行文件。

```powershell
cd C:\englab
.\deploy.ps1 `
  -WinSwPath C:\staging\verified\WinSW-x64.exe `
  -StaticExecutable C:\staging\build\englab_server.exe `
  -CaddyExecutable C:\staging\verified\caddy.exe `
  -OutputDir C:\englab\service-bundle `
  -InstallRoot C:\englab `
  -PythonExecutable C:\englab\backend\.venv\Scripts\python.exe `
  -SecretStorePath C:\englab\secrets\astra-staging.dpapi `
  -Environment staging `
  -PublicOrigin $PublicOrigin
```

`-Environment` 只接受 `staging` 或 `production`，默认值为 `production` 以保持旧调用兼容；它会同时写入 API/worker 的 `ASTRA_ENVIRONMENT` 和生成报告。目标 staging 必须显式传 `-Environment staging`，不能通过手工修改 XML 冒充环境；development 仅用于未纳入目标服务包的本地开发进程。

该入口只调用 `backend/scripts/windows_service_drill_bundle.py` 生成四份 WinSW XML、Caddyfile、二进制副本、SHA-256 清单和可逆命令；不会下载、改防火墙、安装或启动服务。默认端口 9010/9011/9012 仅用于回环演练，正式 80/443/TLS 应由已审批的最外层入口处理。生成后必须先复核：

1. `artifact_hashes` 与组织制品清单一致，报告不含数据库 URL 或 secret。
2. 四份 XML 使用 WinSW 稳定 2.x 的 `serviceaccount/domain + user`，SCM 安装后回读为 `NT AUTHORITY\LocalService` 或已批准的 `NetworkService`，绝不能静默落为 LocalSystem。
3. Caddyfile 同时包含站点地址与显式 `bind 127.0.0.1`，`/api/*` 先于静态 fallback 分流，代理服务不声明上游 SCM 硬依赖。
4. 数据库 DSN 只由服务账号可读环境或 secret store 提供；不得在 XML、命令行、发布历史或普通日志中写入凭据。

### 3.1 Windows DPAPI 密钥存储

V7.4.29 起，当前 Windows staging 使用 `backend/scripts/windows_dpapi_secret_store.py`。`seal` 只从 stdin 读取非空 `ASTRA_*` JSON，使用 DPAPI LocalMachine 加密；专用父目录和密钥文件从创建时即关闭 ACL 继承，只允许 seal 时冻结的操作者 SID、SYSTEM、Administrators 与所选 LocalService/NetworkService。已存在但 ACL 不匹配的父目录直接拒绝，不会静默改造普通目录。操作者 SID与服务账号同时写入加密载荷和外层元数据，LocalService 读取时仍按冻结操作者验证实际 DACL，服务包生成器会再次校验账号一致；任一 ACL、账号或载荷异常均失败关闭。

```powershell
Set-Location C:\englab\backend
$Python = 'C:\englab\backend\.venv\Scripts\python.exe'
$SecretStore = 'C:\englab\secrets\astra-staging.dpapi'

# $SecretJson 只能来自进程内生成或批准的 secret provider；不得打印、写普通文件或进入命令历史。
$SecretJson | & $Python -m scripts.windows_dpapi_secret_store seal `
  --output $SecretStore `
  --service-account 'NT AUTHORITY\LocalService'
Remove-Variable SecretJson -ErrorAction SilentlyContinue

& $Python -m scripts.windows_dpapi_secret_store inspect --store $SecretStore
```

目标 store 至少含 `ASTRA_DATABASE_URL`、`ASTRA_AUDIT_IP_HASH_SALT` 与一次性 `ASTRA_ADMIN_BOOTSTRAP_TOKEN`。`inspect` 只返回 key 名称、数量、服务账号、ACL/operator-bound 布尔状态和 `sensitive_values_returned=false`，不返回操作者 SID；不得把 store 路径或 key 值复制进 target evidence。manifest 的 secret refs 使用三个互不重复的组织内 opaque 引用，不使用 URL、赋值串或明文。

初始化验收时服务包可临时传 `-EnableAdminBootstrap`；浏览器 proof 结束后必须重新生成未带该开关的服务包并重启 API/worker，随后确认 `/api/admin/bootstrap` 已关闭。`run` 只向单个子进程注入显式 `--required-key`，没有列出的 store key 不注入。

### 3.2 当前工作区 staging 的公网 HTTPS 入口

当前机器只有私网地址时，可以使用经官方 checksum 复核的 Cloudflare Quick Tunnel，把随机 `trycloudflare.com` HTTPS origin 转发到回环 `http://127.0.0.1:9012`；官方将 Quick Tunnel 定位为测试/开发用途，因此它只能作为本轮指定 **staging 候选入口**。只有 hostname 在完整证据窗口内稳定、外部探针/本机绑定/防火墙/连接器监控和全部七证据均通过且 OPS/QA 接受后，才可关闭本轮 staging 门禁；它永远不能写成 production 域名、SLA 或正式上线证明。参考：[Cloudflare Quick Tunnels](https://developers.cloudflare.com/cloudflare-one/networks/connectors/cloudflare-tunnel/do-more-with-tunnels/trycloudflare/)。

执行顺序固定为：先启动回环四服务并验证本机分流，再启动隧道；从受控日志读取实际 HTTPS origin 后写入 `$PublicOrigin`，重新生成服务包以固定 CORS origin 和 `Strict-Transport-Security: max-age=31536000; includeSubDomains`，随后重启并从公网回读。Quick Tunnel hostname 每次重建可能变化，变化后旧 manifest/evidence 全部作废，必须重新冻结同一 origin、instance、revision 和 bundle。

公网验收至少从非回环执行面确认 TLS ≥ 1.2、证书剩余期、HSTS、`/api/health`、静态首页和 9011 原始 API 端口不可达；DNS 失败、隧道未运行或仅本机 curl 不能算公网隔离通过。隧道进程不是四个业务 SCM 服务之一，其 PID、版本、checksum、启动/停止时间与日志仍须进入受控运行记录。

目标三角色 proof 必须从 DPAPI store 注入 bootstrap token，禁止 CLI 传值：

该模式要求 API/web 是同一公开 DNS、标准 443 的精确 HTTPS origin；IP、单标签、保留/示例域和非标准端口均失败关闭。health `environment` 必须明确为 `staging` 或 `production`，Git 工作区必须干净且 HEAD 已冻结，`--out` 必须显式指向仓库外不存在或为空的目录。成功后目录内同时生成供诊断的 `role-workflows-report.json` 和可直接交给 `target_release_evidence seal --evidence-id target_browser_smoke` 的 `target-browser-smoke.json`；后者只在 12 项固定语义全部通过时生成，并绑定真实 Edge 版本、当前 40 位 `release_revision`、同一 public origin，敏感返回标志固定为 false。浏览器报告成功后仍要对同一 MySQL 做只读权威总账；任何本地 SQLite proof 都不能替代这一步。

生产推荐把 worker 注册为独立服务，并让 API 与 worker 使用同一数据库、不同进程级环境：API 进程保持 `ASTRA_BACKGROUND_TASK_WORKER_ENABLED=false` 且不启动旧 scheduler；worker 进程按需设置知识/脚本 scheduler 开关后运行：

python -m scripts.run_background_tasks --enable-audit-anchor

只有完成外网访问、host allowlist、出口和凭证评审后，内容脚本 worker 才可设置 `ASTRA_BACKGROUND_TASK_WORKER_CONTENT_SCAN_ENABLED=true` 或传 `--enable-content-scan`；只有完成回执服务评审后才可启用审计锚定 worker。也可设置 `ASTRA_BACKGROUND_TASK_WORKER_ENABLED=true` 让 FastAPI lifespan 启动 worker，但不得再注册第二个相同用途的独立服务；即使误启多个 worker，数据库 claim 仍负责单任务竞争，但会增加连接和锁压力。

故障恢复顺序：

1. 先停止异常 worker，保留数据库任务和 attempt 记录，不手工删除 leased 行。
2. 用 `GET /api/admin/background-tasks/queue` 查看 stale lease、retry_wait 和 dead_letter；单项 payload/lease token 不会通过 API 返回。
3. 普通任务等待 lease 到期后重启 worker；attempt 未耗尽时会自动接管，耗尽后由管理员核对原因并显式 retry 或 cancel。
4. 知识快照或脚本扫描若领域 run 已 success，新 worker 只完成控制面，不重复生成 run。告警 `dispatching` 歧义按前述接收端核对流程处理，禁止盲目 retry。
5. V6.6.61 已完成真实 MySQL lease/cancel/retry/stale-token，V6.6.62 已完成独立服务包装/业务 PID 更替与恢复。生产事故演练仍需记录停止时间、lease 到期/接管时间、attempt、锁等待、连接池、队列积压和核心 API 响应；不得为造强杀证据临时把服务账号提升为 LocalSystem。

### 6.5 反向代理分流

示例策略：

```text
/api/*  -> http://127.0.0.1:8000/api/*
/*      -> http://127.0.0.1:910/*
```

V6.6.62 回环演练采用以下等价 Caddyfile；站点地址本身不能替代显式 `bind`：

```caddyfile
{
    admin off
    auto_https off
}

http://127.0.0.1:9012 {
    bind 127.0.0.1
    @api path /api/*
    handle @api {
        reverse_proxy 127.0.0.1:9011
    }
    handle {
        reverse_proxy 127.0.0.1:9010
    }
}
```

这份配置用于本机服务/回滚演练，不是公网 TLS 模板。正式域名、80/443、证书、HSTS、云安全组和组织 TLS 策略必须在目标环境单独审批；不得为了“看起来像生产”把本机演练端口绑定到 `0.0.0.0`。

代理要求：

- `/api/*` 不做静态缓存，不改写 `Cache-Control: no-store`。
- 透传 `X-Request-ID`；没有上游 request id 时，可由代理生成，也可交给 FastAPI 生成。
- 只信任来自反向代理的 `X-Forwarded-For`，不要把 FastAPI 直接暴露到公网。
- 静态资源仍可按原 Service Worker 与静态缓存策略运行，业务 JSON 只走 Python API 的 no-store 响应。

### 7.2 数据备份与恢复演练

1. 记录冻结提交 hash、Alembic `current/head`、MySQL server version、数据库字符集/排序规则和 UTC/系统时区；记录中不得包含 DSN、密码或 token。
2. 在停止 schema 变更、后台 worker 和外部 dispatch 后，使用受控服务账号执行一致性备份。MySQL 推荐以 `mysqldump --single-transaction --routines --triggers --events` 为基线；是否包含 GTID 参数由目标环境决定，不能直接复制示例覆盖生产策略。
3. 对备份文件计算 SHA-256，写入独立清单并保存到与数据库不同的受控位置；备份、清单和解密材料分开托管。明确保留期、访问人和销毁审批。
4. 不在原库做恢复演练。创建隔离恢复库，导入备份后运行 `alembic current`、`deploy_preflight --require-mysql`、`deploy_smoke --require-mysql` 和最小登录/内容 render/提交批改只读或测试路径。
5. 记录恢复开始/结束时间、数据量、失败重试、最终 revision、表/列缺失、校验和和清理决定。没有独立恢复成功记录时，不能把“备份命令退出 0”写成可恢复。

### 7.3 RC 回滚顺序

1. 宣布 No-Go，冻结管理端内容发布、批改、成员/权限变化和新后台任务；关闭 `ASTRA_BACKGROUND_TASK_WORKER_ENABLED` 及三个外部执行能力开关，保留只读 API/静态页。
2. 若仅 API 代码异常，切换到上一冻结提交/目录并重启 `AstraApi`；保持已前向迁移的数据库，不对 0046 做在线破坏性 downgrade，优先发布兼容修复。
3. 若代理异常，恢复上一份已校验的代理配置并 reload；确认静态站、FastAPI health、request id、no-store 和公网直连阻断恢复。
4. 若迁移造成不可兼容数据问题，停止新旧写入，按变更单恢复独立验证过的备份；恢复前保留故障库只读快照和审计/任务终态证据。`0050 -> 0049` 只删除过期租约恢复索引但会恢复高积压扫描退化风险；`0049 -> 0048` 会失去全部代码题目版本、学生源码与判题记录，`0048 -> 0047` 会失去班级课程发布计划与稳定键，`0047 -> 0046` 会失去组织说明和乐观并发版本，`0046 -> 0045` 会失去知识窗口微秒精度，`0045 -> 0043` 会继续失去审核绑定与安全控制锁。所有降级都必须按变更单验证，不得作为常规在线快速回滚。
5. 恢复后按“health → 登录/会话 → 内容 render → 课程/作业读取 → 提交/批改测试数据 → worker 队列 → 审计链”顺序复核，再决定开放写流量。

## 八、云服务器安全组

除了 Windows 防火墙，还需在云厂商控制台（阿里云/腾讯云/华为云等）的**安全组**中放行：

| 方向 | 协议 | 端口 | 来源 |
|------|------|------|------|
| 入站 | TCP | 910 | 旧式直连 C++ 静态服务时可临时开放；反向代理模式下限制为本机/代理来源 |
| 入站 | TCP | 80 / 443 | 0.0.0.0/0（使用反向代理时） |

> ⚠️ 这一步很容易遗漏，如果 Windows 防火墙已放行但外网仍无法访问，请检查安全组设置。
>
> FastAPI 的 `8000` 建议只监听 `127.0.0.1`，不直接对公网开放。启用反向代理后，`910` 也应优先限制为本机或反向代理来源；只有旧式直连 C++ 静态服务时才把 `910` 作为公网入口。

## 九、故障排查

| 症状 | 排查方法 |
|------|---------|
| 外网无法访问 | ① 检查安全组是否放行 910 ② `Test-NetConnection localhost -Port 910` ③ `netstat -ano \| findstr 910` |
| 服务启动失败 | 查看 `C:\englab\logs\stderr.log`；尝试手动运行 `.\englab_server.exe -p 910 -r C:\englab` 观察报错 |
| 编译失败 (cmake) | 确认已安装 VS Build Tools 的 "C++ 桌面开发" 工作负载；确认 cmake 在 PATH |
| 页面白屏 | `Invoke-RestMethod http://localhost:910/` 检查是否返回 HTML，确认 `-r` 路径正确 |
| 端口被占用 | `netstat -ano \| findstr :910` 找到 PID 后 `taskkill /PID <PID> /F` |
| Python API degraded | `Invoke-RestMethod http://127.0.0.1:8000/api/health`，再查看 `astra-api-stderr.log` 和数据库连接 |
| 预检失败 | 查看 `python -m scripts.deploy_preflight --require-mysql` 输出的 `configuration` / `database` / `migrations` / `compatibility` 字段；先确认 `ASTRA_AUTO_CREATE_TABLES=false`，再修数据库连通、Alembic revision、MySQL 方言、`utf8mb4` 字符集/排序规则；时区、`sql_mode`、连接数异常先进入试运行风险清单 |
| 部署 smoke 失败 | 查看 `python -m scripts.deploy_smoke --require-mysql` 输出的 `preflight` / `schema` / `api` 字段；先确认 preflight 已通过，再检查 `schema.missing_tables`、`schema.missing_columns`、`organization_governance_mismatches`、`organization_version_invalid_rows` 和 `/api/health` 数据库状态 |
| 拓扑演练失败 | 查看 `python -m scripts.deploy_topology_drill ...` 输出的 `target_requirements` / `topology` / `proxied_api` / `direct_api` / `public_exposure` / `service_plan` 字段；重点确认 `/api/health` 命中 `service=astra-backend`、manifest 声明的 API 内层端口未公网暴露、`X-Request-ID` 和 no-store 未被代理改写 |
| 阶段门禁失败或延期 | 查看 `python -m scripts.backend_stage_gate ...` 输出的 `gates` / `blockers` / `missing_evidence` 字段；缺 `--require-mysql`、缺真实拓扑、缺完整测试或缺人工确认时先补证，不要把 `--confirm-*` 当作自动检查 |
| API 被缓存 | 检查代理是否保留 `Cache-Control: no-store`，确认请求命中的是 `/api/* -> :8000` |
