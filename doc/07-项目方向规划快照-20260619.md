# 星序 Astra 项目方向规划快照

> 日期: 2026-06-19  
> 分支: `feature/v6.2`  
> 用途: 记录当前我对项目未来方向的理解，供后续和用户重新对齐。本文不是最终产品规格，而是当前工作状态下的规划口径。

## 1. 当前判断

项目已经从早期的「工科实验室」单一学习站，演进成「星序 Astra」多学科可视化学习平台。这个演进带来了更大的内容覆盖面，但也造成了一个明显偏移：页面数量、学科入口和新模块增长很快，整体方向需要重新收束到「可信、可学、可验证」的学科知识网站，而不是继续无边界扩展视觉模块。

我现在对项目方向的理解是：

- 「星序 Astra」是总入口和品牌层，不应只服务视觉星图效果。
- 「工科实验室」仍是主学习阵地，核心任务是把数学、物理、化学、算法、生物等知识讲准、讲清、讲可操作。
- 新增的地球与宇宙、工程、数据科学、信息技术、材料、人文可视化等方向，应该作为扩展学习入口，但需要经过内容可信度、交互价值和页面一致性三道门槛。
- 「代码空间」作为独立子站保留，主要承接代码执行追踪、算法运行过程和未来信息技术内容，不宜和主站学科页面混在一个交互模型里。

## 2. 需要修正的偏移

### 2.1 从扩张优先转为质量优先

之前的工作更偏向快速补齐新页面、新星系和新模块。后续应改为：

1. 先确认学习目标。
2. 再确认权威资料来源。
3. 再设计交互模型。
4. 最后落地页面与缓存版本。

任何新增学科页都必须回答三个问题：

- 学生在这里能学到什么具体知识？
- 这个知识点的来源和模型边界是什么？
- 交互是否真的帮助理解，而不是只增加视觉复杂度？

### 2.2 从展示型页面转为学习型页面

页面不应只堆叠 hero、卡片和 canvas。每个学科方向都应具备稳定结构：

- 概览: 说明学科问题和学习入口。
- 模型: 说明交互使用的简化模型。
- 实验台: 提供可操作的参数和状态反馈。
- 判读路径: 引导学生如何把图表转回概念。
- 参考资料: 给出权威来源和模型边界。

### 2.3 从内部过程外露转为公开表达干净

公开页面不能出现工作过程、内部复核、调试记录、规划状态、可信度标签等面向开发者的说法。学习者能看到的是学习内容、方法边界和参考资料；内部过程应只存在于文档、提交记录或工作快照里。

## 3. 内容可信度原则

后续所有知识内容应遵循以下原则：

- 优先使用官方课程标准、开放教材、标准组织、大学教材或权威机构资料。
- 页面里只写学习者需要知道的结论、条件和限制，不把「资料复核过程」写成可见内容。
- 涉及近似模型时必须说明模型边界。例如线性回归不能自动外推，Hall-Petch 趋势不能简单推广到所有纳米晶材料，文本词频不能自动等于主题。
- 每个新增模块至少保留 2 到 3 个可追溯来源。
- 对高风险或易误导内容，宁可减少结论，也要补充条件。

## 4. 后续阶段建议

### 阶段 A: 当前版本收束

目标是把已扩展页面整理成一个可解释、可演示、可维护的版本。

重点工作：

- 清理所有公开页面中的内部过程文案。
- 统一新扩展页的结构与响应式行为。
- 对核心页面补齐参考资料和模型边界。
- 修复 service worker 版本、静态预览和移动端 canvas 溢出问题。
- 建立模块验收清单，避免每次新增页面都靠临时判断。

### 阶段 B: 学科内容可信度补强

目标是让网站成为真正可信的学科知识学习站。

重点工作：

- 为数学、物理、化学、生物、算法五大核心学科建立来源索引。
- 为扩展方向建立来源索引: 宇宙/地学、工程、数据科学、信息技术、材料、人文可视化。
- 给每个实验模块补「学习目标」「模型假设」「容易误解点」「参考资料」。
- 对已有题库和说明文案做事实一致性检查。

### 阶段 C: 设计系统收敛

目标是减少页面间的风格漂移。

重点工作：

- 固化扩展页模板: overview、bridge cards、lab、interpretation、reference。
- 为所有实验台统一控件、状态面板、canvas 容器、移动端断点和信息面板密度。
- 将「卡片嵌卡片」「过度装饰」「无学习价值标签」降到最低。
- 保持深色科幻品牌，但让学习内容优先于装饰。

### 阶段 D: 下一轮新能力

只有当阶段 A 到 C 收束后，再考虑继续扩展。

推荐顺序：

1. 信息技术与代码空间联动: 网络分层、编译流程、数据流图。
2. 数据科学: 采样偏差、残差、分类、简单模型比较。
3. 工程应用: 桁架之后补热机、流体管路或机构运动。
4. 地球与宇宙: 季节之后补板块、天气剖面或遥感图层。
5. AI 独立方向: 等代码空间和数据科学稳定后再立项。

## 5. 当前优先级

短期优先级如下：

1. 文档同步和 Git 快照。
2. 清理方向偏差，明确哪些新增页保留、哪些需要降级为候选。
3. 对公开页面做一次内部过程词扫描。
4. 建立全站模块来源表。
5. 分学科修复内容准确性和移动端体验。

## 6. 我对下一步的建议

我建议下一轮不要继续大规模新增页面，而是先做一次「内容和架构对齐」：

- 用这份文档作为方向草案。
- 由用户确认项目是否继续走「星序多学科平台」路线，还是回收为更聚焦的「工科实验室」路线。
- 如果继续多学科路线，就把新扩展页纳入正式验收体系。
- 如果回收为工科实验室路线，就将部分扩展页从主导航降级为未来星图或实验分支。
