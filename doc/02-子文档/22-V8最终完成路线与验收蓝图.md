## 1. 最终完成定义

V8.0 的“完成”不是页面更多、接口更多或测试数量更多，而是同时满足以下终态：

1. 学生在三个学习单元内产生可解释、幂等、可追溯的预测、操作、尝试、错误、修正、完成与迁移证据，并可跨设备续学。
2. 教师能在五分钟内完成一周课程复制、安排、学生视角预览和批量发布，并能直接看到落后学生、共同误区、提交、反馈和逾期状态。
3. 每个课程活动都有明确学习目标、完成条件、误区反馈、迁移任务和教师量规；“访问过”不再等于“完成”。
4. 代码空间使用真实隔离 runner 完成隐藏测试、资源限制、部分得分和稳定诊断，API 进程永不直接执行学生源码。
5. 管理员通过组织关系、数据质量、影响预览、批量领域操作、撤销恢复和审计治理数据，而不是查看原始表或被运维计数淹没。
6. 教师能够使用受约束组件和题型创建、预览、版本化、送审、发布互动课程；脚本能力仍受审核、hash、sandbox 与 CSP 约束。
7. 前后端核心功能按稳定模块边界维护，巨型入口文件停止增长，88 个工科实验全部具备经验证的生命周期协议。
8. 真实规模数据、全站可访问性、弱网/低配设备、真实 MySQL、备份恢复、监控、回滚和安全边界均有可复核证据。
9. 至少完成一轮四周真实课堂试点，教学效果、教师成本、学生完成率和错误类型达到试点前登记的成功阈值；失败必须回到对应任务修正。
10. 学习数据保留、导出、删除、推断解释、纠错和未成年人责任边界形成产品能力与正式政策，经过目标司法辖区的专业复核后才允许生产发布。

规划默认以“高一物理四周课程、2 名教师、30—60 名学生、10 个核心活动”为旗舰验收线。该范围用于建立可测量的第一条完整课堂链，不是永久缩减产品：V7.9 必须把同一质量契约迁移到现有全部课程活动，V8.0 才能完成全项目验收。

## 2. 十项问题与终态任务映射

| 外部评审问题 | 最终结果 | 正式任务 |
| --- | --- | --- |
| 1. 学习闭环未真正接通 | 三个学习单元统一写入权威学习证据，跨设备续学，教师端按秒级刷新可解释进度 | `BE-006`、`FE-012`、`CONTENT-001` |
| 2. 产品定位过于贪心 | 以旗舰课堂为主路径，星序首页只呈现真实可达能力、今日任务、上次位置、截止与问题，不用营销名称替代能力 | `PM-009` |
| 3. 内容数量超过深度 | 先完成 10 个旗舰活动，再把预测—实验—解释—迁移—量规质量契约迁移至现有全部活动 | `CONTENT-001`、`CONTENT-002` |
| 4. OJ 只有契约没有产品 | 隔离 runner、隐藏测试、限时限存、部分得分、诊断、重试与教师审阅形成真实闭环 | `OPS-004`、`BE-008`、`FE-014` |
| 5. 教师工作台像控制面 | 教师使用自然教学语言完成周计划、学生预览、批量发布、催交、退回、复用、逾期策略和学情处置 | `UX-003`、`BE-007`、`FE-013` |
| 6. 管理台形成可观测性幻觉 | 学校管理员首先看到组织关系、学习业务、异常数据和影响范围；运维指标退居专门诊断区 | `DATA-001`、`UI-003` |
| 7. 教师可配置课程只有半真 | 教师能创建受约束互动内容和题目步骤，完成版本、预览、审核、发布、回滚与复用 | `BE-009`、`FE-015`、`CONTENT-002` |
| 8. 技术债务过重 | 建立并执行模块依赖规则，拆分前后端巨型职责，移除散落全局状态并清零实验 legacy 生命周期 | `ARCH-001`、`FE-016`、`BE-010`、`TOOLS-001` |
| 9. 测试证明被高估 | 使用学期级数据、真实设备/网络、全站键盘与 Canvas 替代、真实课堂和学科专家复核验证产品 | `UX-001`、`QA-012`、`QA-013`、`PERF-001` |
| 10. 正式发布条件不成立 | 补齐未成年人数据治理、真实 MySQL、TLS、secret、监控、备份恢复、隔离 runner、回滚和生产验收 | `SEC-001`、`OPS-001`、`REL-008` |

`REL-001` 外部 Webhook/issue/audit provider 仍是独立条件项，不属于 V8.0 必备能力；只有用户确认业务价值、provider、owner 与审批后才进入最终范围。

版本推进只认退出门禁，不因日期或代码量自动升级。某个任务失败时停留在原周期修正，不用“后续优化”把未完成内容滚入下一版本。

## 4. 旗舰课堂与全课程迁移

### 4.1 旗舰课程质量契约

10 个旗舰活动每个都必须包含：

1. 可观察、可评价的学习目标和前置知识。
2. 学生操作前的定量或定性预测。
3. 有变量约束和记录要求的实验/互动。
4. 至少一个常见错误模型及针对性反馈。
5. 学生自己的解释或证据选择，不用点击次数代替理解。
6. 与原情境不同的迁移任务。
7. 教师可读量规、答案证据和人工修正入口。
8. `started / predicted / attempted / corrected / completed / transferred` 等权威学习事件。
9. 断网重试、重复提交和跨设备恢复下的一致结果。
10. 学科专家、教师和学生三方验收记录。

### 4.2 全课程迁移

旗舰课堂通过后，`CONTENT-002` 必须盘点工科试验室、代码空间和未来星系的全部现有活动。每个活动只能进入以下终态之一：

- **validated**：满足质量契约并纳入正式课程；
- **demonstration-only**：明确仅供演示，不计入完成度或掌握度；
- **retired**：内容错误、重复或维护成本不合理，保留历史引用但退出学生目录。

不得保留“看起来像课程、实际上没有完成标准”的第四种状态，也不得在全量迁移完成前继续增加活动总数。

## 6. 最终验收证据

| 证据包 | 最低内容 |
| --- | --- |
| 教学内容 | 10 个旗舰活动和全目录清单；学习目标、误区、迁移题、量规、学科专家结论与版本 |
| 学习证据 | 每类事件的 schema、幂等键、完成规则、失败重试、跨设备恢复、教师聚合和审计追踪 |
| 教师效率 | 任务脚本、五分钟周计划指标、学生视角预览、批量处置、逾期规则和教师可用性访谈 |
| OJ | 四语言编译/运行、隐藏测试、资源限制、网络/文件隔离、恶意样例、部分得分、租约恢复和教师审阅 |
| 管理治理 | 组织关系图、异常检测、影响预览、批量操作、冲突、撤销恢复和审计回读 |
| 内容创作 | 新建、编辑、互动组件、题目步骤、预览、送审、发布、回滚、复用、脚本拒绝/审核和版本追踪 |
| 工程维护 | 模块依赖门禁、核心文件职责、88 实验生命周期、前后端测试、依赖锁和无临时/生成物检查 |
| 规模与可访问性 | 学期级数据、30—60 学生班级、多班并发、桌面/390×844、键盘、读屏语义、Canvas 替代、弱网和低配设备 |
| 课堂试点 | 2 名教师、30—60 名学生、四周日志；备课时间、完成率、错误类型、前后测、退出/缺失数据和改进结论 |
| 数据治理与发布 | 保留/导出/删除/解释/纠错策略，目标环境 owner、MySQL、TLS、secret、服务、监控、备份恢复、回滚和同源浏览器证据 |

最终验收不得只引用合同测试数量、审计日志数量或本机截图。自动化、真实浏览器、数据库账本、教师/学生实际任务、学科审查和目标环境证据必须相互一致。

## 7. 停止规则与非目标

- V8.0 前停止增加课程数量；新增内容只能替换、深化或完成已登记课程。
- 停止新增装饰性 Three.js、AI 概念和无教学决策价值的管理指标。
- 不开放任意数据库、SQL、原始 JSON 或宿主脚本编辑。
- 不在 API 进程、浏览器正式提交链或普通 worker 中直接执行未隔离学生源码。
- 不把“教师能完成操作”当作可用性通过；教师效率必须由任务时间和真实反馈证明。
- 不把浏览器预检写成正式 OJ accepted，不把本机 9001 写成 staging/production。
- AI 助教不进入 V8.0 必备范围；只有学习证据、课程质量、教师工作流和数据治理通过后才可另立任务。
- 如果课堂试点未达到预登记阈值，停止正式发布并回到失败任务修正；不得用扩大样本、修改口径或删除失败数据掩盖结果。
