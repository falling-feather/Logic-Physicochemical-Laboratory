## 5. 验收与风险

- 每个版本同时通过任务专项、全量自动化、真实浏览器、数据库账本和文档/项目对接门禁；只证明代码合同的测试不得替代课堂或目标环境证据。
- V7.7 必须证明 10 个旗舰活动和五分钟教师周计划；V7.9 必须证明全课程质量状态、88 实验生命周期、真实规模、全站可访问性和性能；V8.0 必须证明四周课堂与目标环境。
- 风险：旗舰范围继续膨胀、课程迁移把数量误当质量、学习数据最小化不足、真实 runner 隔离失败、教师工作流被系统术语重新绑架、试点选择偏差、目标环境外部依赖和技术债迁移期间的双轨状态。
- 不做：V8.0 前增加课程数量、装饰性 Three.js 或 AI 概念；开放任意 SQL/表/原始 JSON；让 API 或宿主直接执行学生源码；在普通浏览器存储、日志或报告中持久化敏感学习数据；为三星系复制后台；用本机 9001、合同测试数量、满意度或审计计数冒充最终通过。

## 6. 需要用户提供或确认

1. 旗舰验收线默认采用“高一物理四周课程”；若需要更换学段或学科，必须在 `PM-009` 开始前确认，否则按当前默认执行。
2. `QA-013` 开始前需要确定试点学校/教师/学生、伦理与数据授权 owner；没有真实试点主体时 V8.0 不得完成。
3. `SEC-001` 与 `OPS-001` 完成前需要确定目标司法辖区、专业复核人、域名、staging/production owner 和目标基础设施。
4. 是否存在足够业务价值的首个外部 provider；没有则 `REL-001` 继续关闭，且不阻断 V8.0。
