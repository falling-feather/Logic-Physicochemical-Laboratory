## 0. 先读这几条

1. 主站是单页应用，入口只有 [`index.html`](../index.html)。所有主站页面的 DOM 骨架都在这个文件里，用 `section#page-xxx` 区分页面。
2. 主站页面身份与普通页面脚本在 [`shared/js/page-registry.js`](../shared/js/page-registry.js) 登记，路由消费端在 [`shared/js/router.js`](../shared/js/router.js)；工科试验室五大学科页的实验脚本仍由 [`shared/js/module-selector.js`](../shared/js/module-selector.js) 按 `data-module` 懒加载。
3. 工科试验室五大学科页不是“一个实验一个 HTML”。页面骨架在 `index.html`，实验入口由 `data-module="<实验ID>"` 标记，实验逻辑在 `pages/<学科>/<实验>.js`，公共视觉通常在 `pages/<学科>/<学科>.css`。
4. 代码空间是独立子站，入口是 [`codevis/index.html`](../codevis/index.html)，不要和主站的 `shared/`、`pages/` 混用。
5. 如果当前 URL 像 `#physics/energy-conservation`：先找 `section#page-physics`，再找 `data-module="energy-conservation"`，再改 [`pages/physics/energy-conservation.js`](../pages/physics/energy-conservation.js) 和 [`pages/physics/physics.css`](../pages/physics/physics.css)。

三角色资源矩阵由 `AstraPageRegistry` 唯一登记：

| 权威角色 | 登录后允许加载的角色样式/脚本 | 禁止预热或缓存 |

样式必须在会话确认后、应用解锁前完成；页面脚本仍由 Router 在角色守卫通过后懒加载。退出、运行中 401 与跨角色重新认证必须整页重载，因为从 DOM 删除 `<link>` 不能卸载已经执行的 JavaScript。静态文件可被公开 URL 请求并不代表获得业务权限，后端仍需对每个 API 做角色与作用域授权。

## 3. 工科试验室实验模块索引

定位一个实验时按这个顺序查：

1. `shared/js/config.js` 的 `CONFIG.experiments[subject]`：决定画廊卡片标题、描述、图标和排序。
2. `index.html` 中 `data-module="<module-id>"` 的 `content-section`：决定该实验的静态 DOM、按钮、canvas、信息面板。
3. `shared/js/experiment-registry.js`：决定打开实验时加载哪个 JS、调用哪个初始化函数，登记 cleanup 状态，并只为 `verified:true` 条目提供冻结的模块级 cleanup 报告。
4. `shared/js/module-selector.js`：消费注册表，负责按需加载、初始化、模块切换事务、generation 防迟到任务、公共实验工具关闭与唯一整页离开入口。
5. `pages/<subject>/<subject>.css`：大部分实验视觉样式集中在学科 CSS 内；个别实验的局部 class 也在这里。

当前核对结果：`CONFIG.experiments`、`AstraExperimentRegistry` 与 DOM 均覆盖 88 个唯一实验 ID，学科数量为数学/物理/化学/算法/生物 `20/20/17/12/19`；DOM 共 90 个节点，其中 `searching` 使用 3 个 section。注册表 cleanup 状态保持 `65 legacy-callback / verified:false + 23 validated-callback / verified:true + 0 missing`。模块切换与返回画廊只对 23 项已验证 owner 执行精确 cleanup；65 项 legacy 全部 fail closed。物理和生物仍通过 `_pageEnhancementScripts` 追加学科级 Zoom/页面增强脚本，模块转场和整页离开都会先关闭 Zoom；模块 cleanup 成功后删除 init 标记以允许重新 init，失败则保留旧 DOM/hash/state。整页离开由 `cleanupPage()` 兼容处理，并避免与已执行的精确 cleanup 双调用。`sorting` 的 `SortingLab` 负责取消并 settle 排序计时任务，`cell-structure` 的 `CellStructure` 负责 RAF、Observer、DOM/Canvas 监听器和长按 timeout。

## 6. 新增或重绘页面的登记规则

1. 改页面 DOM：在本文件对应表格补 `section#page-*` 或 `section#cv-page-*`。
2. 改主站页面身份、脚本或页面钩子：同步更新 `shared/js/page-registry.js`；代码空间仍按 `codevis/shared/js/main.js` 的 `CvRouter.register` 维护。
3. 改工科实验模块：同步更新 `shared/js/config.js` 的 `CONFIG.experiments`、`shared/js/experiment-registry.js` 和 `data-module` DOM，并在本文第 3 节登记；禁止恢复 ModuleSelector/Router 私有脚本或 destroy 清单。
4. 新增实验只有完成真实 owner、Zoom/取消资源和切换/离开验证后才能登记 `validated-callback / verified:true` 并进入 `cleanupModule()`；owner 或 Zoom 失败必须阻止转场，legacy callback 不得在模块级执行。新增异步加载、重试、resize、焦点或相关推荐 timer 必须绑定当前 transition generation。
5. 新增页面 CSS：普通主站或代码空间页面确认 `index.html` / `codevis/index.html` 已加载；三角色页面 CSS 只能登记到 `AstraPageRegistry.styles`，不得恢复静态首屏加载。
6. 视觉重绘完成后，至少检查桌面和移动端 hash 直达路径，例如 `#physics/energy-conservation`、`#frontier`、`/codevis/#trace`。
7. `#admin`、`#teacher`、`#student` 是 englab 壳内的非课程页：登记到 `AstraPageRegistry` 但不加 `course` 标签；角色可见性与越权回落只改 `app-session.js`，不要复用课程页的 `[data-module]` / `.content-section` 语义。
8. 三端页面新增或更新静态资源时，只在 `shared/js/page-registry.js` 同步角色矩阵与版本，并确认 `index.html`、`shared/js/main.js`、`sw.js` 没有把它们重新放入公共清单；同时复查 hash 直达、越权回落、退出/401/跨角色清理与移动端导航可达性。V7.4.26 当前统一代际为 `20260716v7426ModuleSwitchLifecycleP4`，不得只修改单一入口造成旧角色资源混用。
9. 三端和后端 schema 请求统一使用 `AstraApiClient`：只使用 HttpOnly Cookie，禁止 `Authorization`、敏感 localStorage/sessionStorage 和写请求自动重试；401/离线/网络失败必须清空旧业务 DOM，恢复只做权威读取。
10. Service Worker 的 API 判断必须位于 navigation、扩展名和静态 cache 逻辑之前；任何 `/api` 动态响应都不得进入 CacheStorage 或离线 fallback。三角色 CSS/JS 的精确 network-only 判断同样必须先于通用静态 stale-while-revalidate 分支。
