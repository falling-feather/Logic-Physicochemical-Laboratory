## 0. 先读这几条

1. 主站是单页应用，入口只有 [`index.html`](../index.html)。所有主站页面的 DOM 骨架都在这个文件里，用 `section#page-xxx` 区分页面。
2. 主站路由在 [`shared/js/router.js`](../shared/js/router.js)。普通页面脚本看 `Router.pageScripts`；工科试验室五大学科页的实验脚本由 [`shared/js/module-selector.js`](../shared/js/module-selector.js) 按 `data-module` 懒加载。
3. 工科试验室五大学科页不是“一个实验一个 HTML”。页面骨架在 `index.html`，实验入口由 `data-module="<实验ID>"` 标记，实验逻辑在 `pages/<学科>/<实验>.js`，公共视觉通常在 `pages/<学科>/<学科>.css`。
4. 代码空间是独立子站，入口是 [`codevis/index.html`](../codevis/index.html)，不要和主站的 `shared/`、`pages/` 混用。
5. 如果当前 URL 像 `#physics/energy-conservation`：先找 `section#page-physics`，再找 `data-module="energy-conservation"`，再改 [`pages/physics/energy-conservation.js`](../pages/physics/energy-conservation.js) 和 [`pages/physics/physics.css`](../pages/physics/physics.css)。

## 3. 工科试验室实验模块索引

定位一个实验时按这个顺序查：

1. `shared/js/config.js` 的 `CONFIG.experiments[subject]`：决定画廊卡片标题、描述、图标和排序。
2. `index.html` 中 `data-module="<module-id>"` 的 `content-section`：决定该实验的静态 DOM、按钮、canvas、信息面板。
3. `shared/js/module-selector.js` 的 `_moduleScripts` 与 `_initModule`：决定打开实验时加载哪个 JS、调用哪个初始化函数。
4. `pages/<subject>/<subject>.css`：大部分实验视觉样式集中在学科 CSS 内；个别实验的局部 class 也在这里。

当前核对结果：`shared/js/config.js` 的 `CONFIG.experiments` 与 `shared/js/module-selector.js` 的 `_moduleScripts` 均覆盖工科试验室 88 个实验 ID；物理和生物还会通过 `_pageEnhancementScripts` 追加 zoom/页面增强脚本。

## 6. 新增或重绘页面的登记规则

1. 改页面 DOM：在本文件对应表格补 `section#page-*` 或 `section#cv-page-*`。
2. 改页面脚本路径：同步更新 `shared/js/router.js` 的 `pageScripts` 或 `codevis/shared/js/main.js` 的 `CvRouter.register` 说明。
3. 改工科实验模块：同步更新 `shared/js/config.js` 的 `CONFIG.experiments`、`shared/js/module-selector.js` 的 `_moduleScripts`，并在本文第 3 节登记。
4. 新增页面 CSS：确认 `index.html` 或 `codevis/index.html` 已加载；如果是运行时动态加载，也要在本文写明加载位置。
5. 视觉重绘完成后，至少检查桌面和移动端 hash 直达路径，例如 `#physics/energy-conservation`、`#frontier`、`/codevis/#trace`。
6. `#admin`、`#teacher`、`#student` 是 englab 壳内的非课程页：只登记到 `Router.pageScripts/pageReadyChecks`，不要加入 `coursePages`，也不要复用课程页的 `[data-module]` / `.content-section` 语义。
7. 三端页面新增或更新静态资源时，必须同步 `index.html`、`shared/js/router.js`、`shared/js/main.js` 与 `sw.js` 的真实版本和资源清单，并复查 hash 直达、离页清理与移动端导航可达性。
8. 三端和后端 schema 请求统一使用 `AstraApiClient`：只使用 HttpOnly Cookie，禁止 `Authorization`、敏感 localStorage/sessionStorage 和写请求自动重试；401/离线/网络失败必须清空旧业务 DOM，恢复只做权威读取。
9. Service Worker 的 API 判断必须位于 navigation、扩展名和静态 cache 逻辑之前；任何 `/api` 动态响应都不得进入 CacheStorage 或离线 fallback。
