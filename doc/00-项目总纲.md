## 1. 项目定位

星序 Astra 是面向高中与大学初阶学习者、教师和平台管理员的多星系可视化学习平台。产品以交互实验和知识探索为学习入口，以 FastAPI 业务后端承接账号、组织、课程、作业、内容、学习分析、后台任务与审计治理。

一级产品入口包括：

| 星系 | 定位 | 当前入口 |
| --- | --- | --- |
| 工科试验室 | 数学、物理、化学、算法、生物五大学科与 88 个交互实验 | 主站 SPA |
| 代码空间 | JavaScript、Python、C、C++ 代码执行追踪与可视化 | `codevis/` 独立子站 |
| 未来星系 | 地球与宇宙、工程、数据、信息、材料、人文等跨学科方向 | 主站独立星系页面 |

用户进入星序应用外壳前必须完成账号认证。角色由服务端 Session 权威确定：学生仅进入学习域，教师增加教学管理域，管理员增加全局治理域；前端显示不得替代后端授权。

## 2. 系统组成

```text
浏览器
├── 主站 SPA：index.html + shared/ + pages/
├── 代码空间：codevis/
└── HttpOnly Cookie 会话
          │
          ▼
FastAPI 业务后端：backend/
├── 认证与用户
├── 学校、班级、课程、作业
├── 内容、学习分析与知识快照
├── 告警、后台任务与审计
└── 管理概览与受约束治理
          │
          ▼
SQLite 开发环境 / MySQL 发布环境

静态交付：Node 开发静态服务 / C++ Release 静态服务
公开入口：Caddy 将 /api/* 转发到 FastAPI，其余静态请求转发到静态服务
```

技术路径、准确文件、接口、生命周期、启动和维护方法见 [`01-开发者手册.md`](01-开发者手册.md)。

## 4. 开发与发布边界

- V7.4.11 已完成登录前置、三角色会话与路由裁剪、管理领域数据地图、管理 API 分域以及 Python/Node/C++ 可复现依赖和产物追踪。
- 后端阶段已经收束，当前不再以增加接口数量为主线。
- V7.4.21 起后端重构严格按 09 的 R1—R6 顺序推进：认证契约、角色资源、组织治理、当前构建终验和目标环境发布不得混成单次提交。
- V7.4.22 已固定浏览器 Cookie-only、非浏览器 Bearer-only 的单请求单通道认证边界；混合、重复或畸形凭据必须 fail closed，前端不得用显示逻辑或兼容 token 绕过服务端 Session 权威。
- V7.4.23 已实现把三角色 CSS/JS 从静态首屏、HTTP fallback 和 Service Worker 共享缓存移出；只有服务端会话确认后才能按学生、教师、管理员矩阵加载，退出、401 或角色变化必须清除旧角色资源并重新建立应用执行域。资源裁剪不是授权边界，任何受保护数据与写操作仍由后端权限决定；R2 仍待 QA-008 对精确提交独立验收。
- 指定目标环境的域名、TLS、secret store、正式 MySQL、备份恢复、日志监控与发布回滚证据仍未闭环；在 `OPS-001` 完成前不得宣称面向真实用户的完整发布完成。
- Webhook、GitHub issue sync、audit anchor、OJ 和 AI 助教仍属于独立审批或产品决策范围，默认关闭。

## 5. 协作入口

当前项目启用“主开发总控 + 长期 FE/OPS/QA 任务 + `houduan` 单写集成”的对接模式：

1. 主开发在 [`02-项目规划.md`](02-项目规划.md) 建立任务、分配小版本、控制 Git 写入与集成顺序。
2. FE 和 OPS 长期任务负责方案审查与边界建议；没有主开发发出的写锁和版本令牌时不得修改仓库。
3. QA 长期任务负责独立验证和退回；验收结论必须回写任务卡或开发历史。
4. 现有 `qianduan` worktree 含未提交成果，当前暂停且禁止清理；详细状态以 [`02-项目规划.md`](02-项目规划.md) 的工作树登记为准。
5. 本项目提交标题继续遵守 `.codex/AGENTS.md`：`Vx.y.z 中文说明`。责任组与任务编号只在任务卡和开发历史中追踪。
