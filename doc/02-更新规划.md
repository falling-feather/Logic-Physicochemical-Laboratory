## 一、当前规划焦点

v6.5 的核心方向是把星序从“静态前端站点 + 轻量静态服务”推进到“可登录、可管理、可生成内容的教学平台”。

当前只保留影响下一步判断的现状：

1. 现有 C++ 服务主要承担静态托管、健康检查、服务器信息和占位 API。
2. 主站教学内容仍大量由前端静态页面、配置和脚本直接承载。
3. 项目已新增 Python 后端首切片，并建立本地账号、密码策略、登录失败锁定、用户、学校、班级、班级加入申请审批与管理端队列、会话、课程、作业、学习事件、作业提交、作业只读复盘、批改、积分流水、个人进度摘要、知识状态/班级规则统计、个人/班级知识快照、知识快照周期重算脚本/运行记录/进程内调度器、管理端 API、学校/班级深度统计、管理端列表分页搜索、待批改队列、审计元数据、认证事件审计、学校/班级/课程访问控制服务层、跨范围权限矩阵测试、内容 seed 启动初始化与读取无副作用边界、正式内容初始化入口、ContentDraft 草稿与脚本审核、脚本静态分析风险等级、脚本 sandbox 契约、公开 render 脚本 manifest 脱敏、脚本历史版本 rollback 重审门禁、草稿编辑、提交/退回/撤回工作流、内容发布/版本记录/追加式回滚、内容页 current 指针、草稿 base version/hash、active key 数据库唯一约束、版本 previous 链、发布元数据、管理端版本 JSON path diff 与 semantic 富语义摘要、API no-store 缓存边界、部署预检、部署 smoke 门禁和前端 opt-in schema 渲染试点；真实 iframe/worker 执行隔离、CSP 强制、脚本资产 allowlist/SRI、多 worker 调度锁、真实服务部署验证、管理端正式 UI、审计导出/防篡改/高频策略和真实 MySQL 联调仍未闭环。

## 四、本阶段不做事项

1. 不立即删除当前 C++ 静态服务。
2. 不一次性重写全部前端页面。
3. 不把学生访问历史、知识状态或作业数据存入普通前端缓存作为正式方案。
4. 不让教师自定义脚本绕过审核或安全讨论直接公开执行。
5. 不在首阶段把代码空间运行记录、AI 助教和 OJ 判题做成完整作业闭环，只预留模型接口。
6. 不在本文展开已完成 v6.3 / v6.4 历史细节；需要查历史时看 `03-发布历史.md`。
