## 一、当前核心纠偏

### 1.1 正确的项目层级

后续所有设计、文案、路由和导航必须遵循以下层级：

| 层级 | 含义 | 示例 | 页面责任 |
| ---- | ---- | ---- | -------- |
| 全局统称 | **星序 Astra** 是整个项目的总称和总览入口，不是每个子页面都要展示的页面品牌 | `#planets` / 星序总览页 | 展示全部星系、承载一级星系导航 |
| 一级菜单 | **星系** 是项目的一级分块 | 工科试验室、代码空间、未来星系 | 每个星系拥有自己的命名、视觉系统、顶栏、页脚和内容结构 |
| 二级菜单 | **星系内的学科/知识目录** | 数学、物理、化学、算法、生物；或未来星系下的地球与宇宙、材料、工程等 | 在所属星系内部组织知识内容，不越级承担全局导航 |
| 内容模块 | 具体交互实验、知识页面或工具 | 函数图像、桥梁桁架、网络分层等 | 服务具体学习目标、模型边界和交互任务 |

关键修正：**星序不是工科试验室的页面名，也不是未来星系页面的页脚品牌。星序只作为全局项目与总览入口出现。**

### 1.2 已暴露的严重误区

v6.2.x 中，未来星系相关板块已经被快速接入，但它们错误沿用了工科试验室星系的 UI 壳，包括页面布局、顶栏、侧边栏、页脚和部分快捷跳转。这是架构层面的错误，不是局部样式问题。

当前需要纠正的误区：

- 把“未来星系”的二级内容当成工科试验室里的新学科页面。
- 把工科试验室的 module-selector、学科页 Hero、侧边栏和页脚直接套到未来星系内容上。
- 在工科试验室页面的顶栏或页脚中继续显示“星序 Astra”作为页面品牌。
- 在工科试验室页面页脚中放入不属于本星系的跨星系快捷跳转，例如地球与宇宙、数据科学、信息技术、材料、工程、人文可视化。
- 把已完成的实验补充、MVP 接入和历史修复继续堆在 02 文档里，增加下一步规划负担。

### 1.3 v6.3 的总目标

v6.3 不做继续扩张。v6.3 的核心目标是：

1. 恢复星序的正确信息架构：星序总览页 -> 一级星系 -> 星系内二级知识目录 -> 具体内容模块。
2. 为“未来星系”重建独立 UI 风格，禁止继续照搬工科试验室。
3. 修复工科试验室页面的品牌、顶栏、页脚和快捷跳转归属。
4. 将已完成内容迁入历史文档，把 02 保持为轻量规划文档。
5. 在开发者文档中写入硬规则，防止后续再次把星系和学科目录混用。
