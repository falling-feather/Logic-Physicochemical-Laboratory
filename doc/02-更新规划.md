## 四、推荐阶段顺序

### 阶段 A：可登录、可发布、可回滚

优先完成 `OPS-01`。该项关闭前，不宣布“面向真实用户的完整发布”完成；`AUTH-UI-01`、`QA-E2E-01`、`IA-AUTH-02` 已分别在 V7.3.0、V7.3.1、V7.4.0 关闭。

### 阶段 B：结构性维护

在发布链稳定后执行 `ARCH-FE-01`、`BUILD-01`、`A11Y-01`；`ARCH-BE-01` 已在 V7.4.1–V7.4.8 独立完成。每次只拆一个边界，禁止把前端壳重构、依赖升级和 UI 改版混在同一提交中。

### 阶段 C：选择性扩展

`PERF-01`、`INTEGRATION-01`、`PRODUCT-02` 只在有真实数据、明确 owner 和审批结论时启动，不作为当前 P0 完成度的一部分。

## 五、依赖与风险

- **目标环境依赖**：域名、证书、MySQL、服务账号和 secret store 需要外部资源；缺少这些条件时只能完成本地门禁，不能伪造上线证据。
- **认证回归风险**：后续改动必须保持“会话确认早于 Router 启动”、学生/教师自助注册、管理员受控初始化、受保护脚本不越权加载和 cookie-only 语义，不能在前端自创弱校验、读取 HttpOnly Cookie 或持久化 token。
- **前端大文件拆分风险**：`admin.py` 已由 69/67 兼容快照保护并完成分域；`index.html` 仍承载大量既有契约，后续拆分必须以页面注册表、行为快照和全量回归保护，不能以“代码更短”为唯一目标。
- **测试数据风险**：端到端测试必须使用隔离数据库和可回收账号，不能污染真实学习记录或复用生产凭据。
- **依赖漂移风险**：功能提交不得顺手升级依赖；Python 使用哈希锁，Node 使用精确 runtime/npm 与 package-lock integrity，C++ 后续锁定也必须保留显式更新入口、版本来源和 CI 漂移证据。当前 Python 组合的测试导入会发出 Starlette/httpx 过渡期弃用警告，后续独立依赖更新须通过兼容版本或迁移方案消除，禁止只过滤警告。
- **外部集成风险**：外部系统可能出现结果不确定、限流或回执丢失；本地 `BugRecord`/outbox/审计链仍保持权威。

## 六、本阶段不做事项

- 不默认开启 Webhook、GitHub issue sync、audit anchor、Gitee/Jira 或任何入站同步。
- 不一次性重写全部前端，也不把当前后端拆成微服务。
- 不把 token、提交正文、成绩、反馈、知识状态或快照写入 localStorage/sessionStorage。
- 不实现审计源数据删除；归档、派生脱敏和恢复继续要求复验与审批。
- 不在没有教学责任、隐私和成本评审前上线生成式学生画像、AI 助教或 OJ。
- 不为追求“零文件体积”删除发布历史、迁移记录或可复核证据。

- 隔离 MySQL 发布证据专项
- `npm ci --ignore-scripts` 与 `npm test`
- 全部跟踪 JavaScript/CJS/MJS 的 `node --check`
- C++ Release configure/build
- `git diff --check` 与文档链接检查

### 浏览器

- 桌面与 390×844：首页、星系目录、五大学科、代表性 sandbox 实验、登录、学生、教师、管理端。
- 页面身份正确、首屏非空、无意外遮罩、无重复 ID、无横向溢出、核心控件可操作、console 无 error。

### 发布

- MySQL 迁移、preflight、smoke、内容初始化和 stage gate 通过。
- 代理路由、CORS/no-store/request-id、静态公开面和内层端口隔离通过。
- 服务重启、配置回滚、静态二进制回滚和独立数据库恢复均有证据。
