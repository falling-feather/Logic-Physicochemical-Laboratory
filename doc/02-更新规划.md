1. 不立即删除当前 C++ 静态服务。
2. 不一次性重写全部前端页面。
3. 不把学生访问历史、知识状态或作业数据存入普通前端缓存作为正式方案。
4. 不让教师自定义脚本绕过审核或安全讨论直接公开执行。
5. 不在首阶段把代码空间运行记录、AI 助教和 OJ 判题做成完整作业闭环，只预留模型接口。
6. 不在本文展开已完成 v6.3 / v6.4 历史细节；需要查历史时看 `03-发布历史.md`。

| 阶段 | 最低验收 |
| ---- | -------- |
| 后端骨架 | API 本地启动、MySQL 连接可用、健康检查通过、pytest 可运行；部署预检可验证数据库、Alembic head、MySQL 方言和 `utf8mb4` 字符集/排序规则，部署 smoke 可复用预检并验证表结构与 `/api/health` |

## 六、已确认决策

| 编号 | 决策 | 影响 |
| ---- | ---- | ---- |
| D-01 | 第一批后端生成页面选择工科试验室实验页 | 复用既有模块化特色和页面模板，降低试点风险 |
| D-02 | 登录先采用简单本地账号注册 + 登录，并对接 MySQL | 暂不引入强身份验证；先完成基础用户体系，密码策略和失败锁定先落在数据库状态表 |
| D-03 | 需要学校/组织层级；学生 direct join、teacher join request 审批、admin/受控导入 direct join 并存 | 管理端、教师端、学生端都要围绕学校和班级建立资源边界；后续 UI 不应把审批流表现成唯一加入路径，也不应让普通教师绕过审批自助成为班级 teacher |
| D-04 | 教师自定义页面原则上允许脚本，但具体脚本需视情况讨论和审核 | 先搭建扩展框架，为后续更多用户群体辅助开发预留能力 |
| D-05 | 作业首阶段暂不完整接入代码空间运行记录 | 代码空间偏代码测试；后续二期规划 AI 助教和 OJ 作业模块 |
| D-06 | 学生画像先采用规则统计 | 当前已按作业频次、数据量、完成率、正确率和积分做在线聚合，并新增个人/班级聚合快照、周期重算运行记录、进程内调度器、数据库租约防重入、自动心跳、管理端健康摘要、调度积压摘要、告警候选摘要、告警 outbox 入队、人工复核状态流转、队列摘要、批量复核、dispatch dry-run、dispatch plan ledger/validation、协作式取消和手动 requeue；后续再补正式外部告警投递、任务队列、队列执行治理、单元/概念细分或模型分析 |
