### 1.2 每个小版本的强制流程

1. 先在 02 建立或更新唯一任务卡，获得目标版本；未分配版本不得写入。
2. 一次只关闭一个可回滚模块，不把认证、角色资源、组织治理和真实发布混入同一提交。
3. 先证明当前行为，再修改实现；测试夹具必须匹配真实 DOM、请求和数据库语义。
4. 数据库结构变化必须附 Alembic、SQLite 回归、MySQL 门禁与回滚考虑；没有隔离 MySQL 时不得声称生产数据库通过。
5. 权限变化必须同时验证允许路径和越权拒绝；前端隐藏永远不能替代后端授权。
6. UI 变化必须完成桌面与精确 390×844 的真实交互、越权、console、错误层和水平溢出检查。
7. 同一提交同步 01、02、03、07/09 中受影响事实，并使用 `.codex/AGENTS.md` 的 `Vx.y.z 中文说明` 标题。
8. 主开发自测不能替代 QA 独立回执；目标环境证据不能由本地或 CI 合成结果替代。

### 1.3 固定退出门禁

每个版本至少满足：

- 范围内自动化测试通过，且检查项确实覆盖本次行为；
- `git diff --check`、文档兼容校验和项目对接校验通过；
- 缓存、Service Worker、HTTP fallback 与 API `no-store` 边界未漂移；
- 没有敏感 token、Cookie、DSN、SQL 参数、学生正文或审计私有数据进入日志、普通存储和提交；
- 规划中的完成标记只在证据齐全后更新，失败或外部阻塞如实保留；
- 提交后工作区干净，遗留 `qianduan` worktree 不被修改、重置或清理。

### 3.2 R1 — 认证双通道契约硬化

**完成证据**：`shared/js/api-client.js` 继续删除调用方 `Authorization` 并只使用 HttpOnly Cookie；`shared/js/app-session.js` 在 Router 前调用 `/api/users/me`。`backend/app/api/deps/auth.py` 已在会话哈希与数据库查询前解析双通道：Cookie-only 和显式 Bearer-only 保持可用，Cookie+Bearer、重复目标 Cookie、重复 Authorization 与畸形 Authorization 使用静态错误 fail closed，不再允许 header 或同名 Cookie 静默覆盖。

**执行决策**：浏览器继续严格 Cookie-only；非浏览器自动化/API 客户端保留显式 Bearer 兼容，测试 helper 必须显式清空 Cookie jar。`LoginResponse.access_token` 为保持既有非浏览器调用兼容而继续返回，Pydantic/OpenAPI 与后端 README 已明确浏览器必须忽略、不得存储或回传。响应中仍含兼容 token 是已接受的阶段性残余风险，后续若拆分浏览器登录与 API token 颁发，必须作为独立兼容版本执行。

**退出结果**：Cookie-only/Bearer-only 正向路径、混合/重复/畸形凭据、失效/撤销 session、角色变化撤销、登录/登出/重置、OpenAPI 标注和审计脱敏均有回归；认证专项 43 项通过，目标发布门禁 5 项在沙箱外通过，冻结代码的后端全量 397 项收集、392 通过、5 跳过、0 失败。独立安全审查确认静态错误不含 token，并推动补齐重复同名 Cookie 与重复 Authorization 边界。本机运行时为 FastAPI 0.136.3/Starlette 1.1.0，而锁文件固定 Starlette 1.3.1；锁定依赖环境/CI 复验仍作为交付证据边界保留，不冒充已完成。

### 3.3 R2 — 三角色资源级裁剪

**完成证据**：`AstraPageRegistry` 已为 student/teacher/admin 页面登记角色、样式与脚本矩阵；`index.html` 不再静态预载三端 CSS，`sw.js` APP_SHELL 和 `shared/js/main.js` 的核心/星系 HTTP fallback 均已移除三端 CSS/JS。Service Worker 对精确角色资源使用 `fetch(..., { cache: 'no-store' })` 的 network-only 分支，禁止进入共享 CacheStorage。

**目标边界**：身份确定前只加载公共登录外壳；身份确定后按服务端角色加载允许的页面资源。学生不得预缓存 teacher/admin 资源，教师不得预缓存 admin 资源。DOM 是否继续保留不可见骨架可分步处理，但受保护脚本执行、网络预热和 CacheStorage 必须有可复核门禁。

**退出门禁**：学生/教师/管理员分别检查 DOM computed style、脚本执行、请求/缓存键、越权 hash 回落和登出后清理；Service Worker 启用状态下重复验证桌面/390×844。

**退出证据**：会话成功后先清理不允许的旧角色缓存并加载允许样式，再写入内存用户态和解锁 Router；学生只加载 student，教师只加载 teacher，管理员允许 teacher+admin。越权 hash 在脚本加载前回落；登出、冷启动 401、运行中 401 和跨角色重新认证先清理角色资源，已启动应用再整页重载以丢弃旧 JavaScript 执行域。提交态 163 个受跟踪 JavaScript 与 17/17 前端合同通过。QA-008 已对精确提交完成三角色桌面/精确 390×844、越权回落、强制 Service Worker、真实 CacheStorage、401/登出/跨角色生命周期独立复验，无 P0/P1/P2，R2 正式退出；前端资源裁剪仍不替代后端授权。

### 3.4 R3/R4 — 管理组织受约束治理

**R3 完成证据**：`admin_organizations.py` 已提供学校/班级精确 GET/PATCH；schema 只接受名称、地区/年级/学期、说明和 active/archived 状态，强制非空原因与 `expected_version`。服务层使用学校/班级行锁、全局管理员权限锁和原子 compare-and-swap；陈旧版本、无变化、唯一约束、跨校字段注入、最后学校责任人、最后班级教师、活动子班级和父学校未恢复均明确拒绝。成功动作记录 `admin.school/class.update/archive/restore` 审计并返回提交后的权威资源。

**目标边界**：只开放明确 schema 的学校/班级名称、说明、状态或归档动作；写入必须有原因、预期版本或 `updated_at` 并发条件、最后 owner/teacher 等保护、审计记录、成功后权威回读，以及超时/未知结果对账。禁止任意 SQL、任意表、原始 JSON 字段或无约束批量修改。

**R3 退出结果**：Alembic 0047 为学校/班级增加 nullable `description` 和非空默认 `version=1`，SQLite 历史行升级/降级/再升级往返通过，MySQL schema 条件门禁在提供隔离库时执行。26 个组织范围写处理器保留活动学校/班级门禁；归档组织从无显式范围的当前学情、快照、进度和周期任务排除，同时保留作业、提交、事件及管理统计历史读取。后端全量收集 435 项，429 通过，6 项真实 MySQL 证据因未提供隔离库跳过；两组独立只读复审均 PASS、无 P0/P1/P2，R3 退出。

**R4 退出门禁**：管理 UI 双确认、按钮锁定、错误分类、409/超时未知结果权威回读和 390×844 通过；界面不得出现任意 SQL、表名或原始 JSON 编辑入口。

**R4 退出结果**：管理数据地图已显示学校/班级 active/archived 权威统计并进入受限原生 dialog；身份/状态/版本只读，元数据白名单和归档/恢复分离，输入变化撤销双确认，no-op 为零写入。每次操作最多一次 PATCH；2xx 以精确 GET 证明版本递增和字段一致，409 保留草稿并读取最新版本，发送后取消/超时/网络错误保留跨路由写锁且不自动重放。`operationOwner` 隔离 PATCH 进行中离开/重进 admin 的旧新生命周期，归档组织同步使教师成员/成绩/策略写入只读并向学生显示 `class_archived`。凭据型 CORS 已允许 PUT，角色资源与 Service Worker 代际统一为 `20260716v7425OrganizationGovernanceP0`。

**R4 验证证据**：163 个受跟踪 JavaScript、18/18 前端合同与组织治理/CORS 定向后端 40 项通过；一次性 SQLite 升级 Alembic 0047 后，本机 Edge 覆盖三角色桌面/390×844、越权、焦点/Escape、44px、2xx 权威不一致、409、歧义结果、归档/恢复、教师只读和真实 PATCH 销毁/重入，报告 `ok=true`、一次 PATCH、显式对账零重放且无浏览器问题。UI、SEC、最终测试三组独立只读复审均 PASS、无 P0/P1/P2。该主开发证明只关闭 R4，不替代 R5/QA-007，也不新增真实 MySQL、staging 或目标环境证据。
