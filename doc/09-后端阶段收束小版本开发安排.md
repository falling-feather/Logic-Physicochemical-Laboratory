### 1.2 每个小版本的强制流程

1. 先在 02 建立或更新唯一任务卡，获得目标版本；未分配版本不得写入。
2. 一次只关闭一个可回滚模块，不把认证、角色资源、组织治理和真实发布混入同一提交。
3. 先证明当前行为，再修改实现；测试夹具必须匹配真实 DOM、请求和数据库语义。
4. 数据库结构变化必须附 Alembic、SQLite 回归、MySQL 门禁与回滚考虑；没有隔离 MySQL 时不得声称生产数据库通过。
5. 权限变化必须同时验证允许路径和越权拒绝；前端隐藏永远不能替代后端授权。
6. UI 变化必须完成桌面与精确 390×844 的真实交互、越权、console、错误层和水平溢出检查。
7. 同一提交同步 01、02、03、07/09 中受影响事实，并使用 `.codex/AGENTS.md` 的 `Vx.y.z 中文说明` 标题。
8. 主开发自测不能替代 QA 独立回执；目标环境证据不能由本地或 CI 合成结果替代。

### 1.3 固定退出门禁

每个版本至少满足：

- 范围内自动化测试通过，且检查项确实覆盖本次行为；
- `git diff --check`、文档兼容校验和项目对接校验通过；
- 缓存、Service Worker、HTTP fallback 与 API `no-store` 边界未漂移；
- 没有敏感 token、Cookie、DSN、SQL 参数、学生正文或审计私有数据进入日志、普通存储和提交；
- 规划中的完成标记只在证据齐全后更新，失败或外部阻塞如实保留；
- 提交后工作区干净，遗留 `qianduan` worktree 不被修改、重置或清理。

### 3.2 R1 — 认证双通道契约硬化

**当前证据**：`shared/js/api-client.js` 删除调用方 `Authorization` 并只使用 HttpOnly Cookie；`shared/js/app-session.js` 在 Router 前调用 `/api/users/me`。但 `backend/app/api/deps/auth.py` 当前 Bearer 优先于 Cookie，`LoginResponse` 仍返回 `access_token`，后端测试和非浏览器工具保留 Bearer 使用。

**执行决策**：浏览器继续严格 Cookie-only；非浏览器自动化/API 客户端保留显式 Bearer 兼容。请求同时携带 Cookie 与 Bearer 时必须 fail closed，不允许一个凭据静默覆盖另一个。登录响应中的兼容 token 是否继续返回，必须在同版通过 schema、OpenAPI、后端 README 和测试明确，不得让浏览器读取或持久化。

**退出门禁**：Cookie-only/Bearer-only 正向路径、混合凭据、畸形 header、失效/撤销 session、角色变化撤销、登录/登出/重置全部有测试；日志和审计不出现原 token。

### 3.3 R2 — 三角色资源级裁剪

**当前证据**：Router 已在脚本加载前检查角色，section 使用 hidden/inert；但 `index.html` 预载三端 CSS，`sw.js` APP_SHELL 和 `shared/js/main.js` HTTP fallback 仍包含 admin/teacher/student 全部资源。

**目标边界**：身份确定前只加载公共登录外壳；身份确定后按服务端角色加载允许的页面资源。学生不得预缓存 teacher/admin 资源，教师不得预缓存 admin 资源。DOM 是否继续保留不可见骨架可分步处理，但受保护脚本执行、网络预热和 CacheStorage 必须有可复核门禁。

**退出门禁**：学生/教师/管理员分别检查 DOM computed style、脚本执行、请求/缓存键、越权 hash 回落和登出后清理；Service Worker 启用状态下重复验证桌面/390×844。

### 3.4 R3/R4 — 管理组织受约束治理

**当前证据**：管理台已有领域计数、连接、角色分布、用户角色/状态双确认和加入申请审批；`admin_organizations.py` 对学校/班级仅提供列表与统计，对加入申请提供 PATCH。学校和班级缺少管理员可用的白名单元数据/状态变更闭环。

**目标边界**：只开放明确 schema 的学校/班级名称、说明、状态或归档动作；写入必须有原因、预期版本或 `updated_at` 并发条件、最后 owner/teacher 等保护、审计记录、成功后权威回读，以及超时/未知结果对账。禁止任意 SQL、任意表、原始 JSON 字段或无约束批量修改。

**退出门禁**：API 正向/越权/冲突/最后责任人/跨校边界测试；Alembic 仅在确需字段时追加；管理 UI 双确认、按钮锁定、错误分类、权威回读和 390×844 通过。

### 3.5 R5/R6 — 终验与发布

R5 必须使用一次性隔离数据库和三个独立账号完整覆盖：学生登录、加入班级、查看/提交作业；教师登录、建课/发布/批改；管理员登录、数据地图、用户/组织治理、审计对账；同时验证越权拒绝、移动端和控制台。主开发浏览器自测不替代 QA-007。

R6 只在用户提供指定目标域名、运维 owner、备份保留期、监控渠道和环境访问权后启动。执行 [`04-部署指南.md`](04-部署指南.md) 的目标 manifest、preflight、smoke、topology、stage gate、端口隔离、独立库恢复和回滚。缺任一外部证据时保持“阻塞”，不得用本地/CI 证明正式上线。

## 5. 非目标与停止条件

- 当前不开放任意数据库表编辑、SQL 控制台或绕过领域 API 的“低代码”写入。
- 当前不启动 OJ、AI 助教、Webhook、GitHub issue sync 或 audit anchor 的真实外部接入。
- 当前不因前端 hidden、旧测试通过或 15/15 历史门禁而宣布正式目标上线。
- 当前不一次性重写认证、三端页面或 88 个实验；每个版本必须可独立回滚。
- 发现 P0 数据泄露、权限绕过、不可恢复迁移或写入结果不确定且无法对账时，停止当前阶段并先建立修复任务。
