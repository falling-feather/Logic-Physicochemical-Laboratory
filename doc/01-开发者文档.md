## 1. 系统全貌

星序由主站 SPA、代码空间子站、FastAPI 业务后端、数据库和静态交付服务组成。浏览器先通过 `/api/users/me` 确认服务端 Session，再启动 Router；学生、教师和管理员的导航、section 与受保护脚本按权威角色裁剪。

```text
主站 index.html / shared / pages ──┐
代码空间 codevis ──────────────────┼──> 浏览器 + HttpOnly Cookie
                                   │             │
                                   │             ▼
Node/C++ 静态服务 <────────────────┘      FastAPI backend
                                                  │
                                      SQLite 开发 / MySQL 发布
```

当前稳定集成基线为 V7.5.11，`main` 保留已验收基线，后续修改从 `houduan` 展开。V7.4、V7.5 和 review 的逐提交过程、精确候选、测试数量与分支收束证据统一见 [`03-开发历史.md`](03-开发历史.md)；当前及未完成任务只见 [`02-项目规划.md`](02-项目规划.md)。用户仍将真实 MySQL、隔离 runner、域名和公网 R6 后置，本机 9001 结果不得外推为 staging/production。

| 范围 | 当前实现 |
| --- | --- |
| 星序入口与角色 | 登录后统一进入 `#planets`；学生、教师、管理员按服务端 Session 加载各自工作区，越权深链在受保护脚本加载前回落 |
| 三个学习单元 | 工科试验室提供 88 个实验；代码空间与未来星系均提供 6 组/18 活动的目录—子课—互动路径 |
| 课程与教师编排 | Alembic 0048—0050 提供班级发布计划、进度聚合、题目/不可变版本、代码提交、判题尝试和有界租约恢复；教师工作台按三星系统一管理课程节奏 |
| 管理与审计 | `#admin` 是唯一全局治理入口；组织写入只接受受限白名单、原因、乐观并发和权威回读，不提供任意 SQL/表编辑 |
| 运行与交付 | `astra-local.ps1` 从 9001 同源提供本机验收；目标环境仍必须通过 [`04-部署指南.md`](04-部署指南.md) 的独立 MySQL、TLS、服务、恢复和证据门禁 |

## 3. 启动与验证

从仓库根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\astra-local.ps1
```

访问 `http://127.0.0.1:9001/`，用 `Ctrl+C` 停止。首次需要管理员时在尚无管理员的本机数据目录使用 `-BootstrapAdmin`，密码只经隐藏交互输入。该命令是默认验收方式；若需分别调试静态与 API，再使用下面的双终端方式：

```powershell
npm ci --ignore-scripts
node server/dev-static-server.mjs --port 8766
```

另一个终端执行：

```powershell
Set-Location backend
python -m pip install --require-hashes -r requirements.lock
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

联调入口为 `http://127.0.0.1:8766/?backendSchema=1&apiBase=http%3A%2F%2F127.0.0.1%3A8000#home`。完整环境、正常结果和失败排查见 [`README.md`](../README.md) 与 [`04-部署指南.md`](04-部署指南.md)。

提交前最低验证：

```powershell
python -m pytest backend
npm test
git diff --check
```

## 4. 扩展与维护边界

- 新增主站页面前先在 [`02-项目规划.md`](02-项目规划.md) 建立任务，再同步 `AstraPageRegistry`、DOM 导航身份、脚本/钩子、HTTP fallback、Service Worker 和契约；角色权限继续只由 `app-session.js` 掌管。
- 新增实验需同步 `CONFIG.experiments`、`AstraExperimentRegistry`、`data-module` DOM 和对应实现文件；脚本/init/cleanup 状态只在注册表登记，`ModuleSelector` 是运行入口，Router 不再维护实验清理表。
- cleanup 边界保持 65 项 `legacy-callback / verified:false`、23 项 `validated-callback / verified:true`、0 项 `missing`。`AstraExperimentRegistry.cleanupModule(subject, id)` 只执行精确 `verified:true` owner，并返回冻结报告 `unknown`、`unverified`、`owner-unavailable`、`cleaned` 或 `failed`；65 项 legacy 绝不执行模块级 callback。`openModule()` 的 A→B 与 `closeModule()` 的 B→画廊会先关闭学科 Zoom，再清理当前已验证 owner；owner/Zoom 失败在 DOM、hash 和 active state 变化前中止。成功 cleanup 删除初始化标记以允许重新 init；legacy 保留初始化标记。transition generation 会取消或失效旧资源加载、init 重试、resize、焦点和相关推荐 timer，dirty legacy 不得在同页重复 init；整页离开继续由 `cleanupPage()` 兼容清理，并通过 `skipExperimentCleanup` 防止双执行。
- `index.html`、`APP_SHELL` 与星系 HTTP fallback 不得静态包含三角色 CSS/JS。`AstraPageRegistry` 维护页面角色与样式/脚本矩阵，`app-session.js` 仅在 `/api/users/me` 成功后加载允许样式；Router 只在角色守卫通过后加载页面脚本。三端资源由 Service Worker 使用 `cache: no-store` 的 network-only 分支处理，退出、运行中 401 与跨角色重新认证必须清理角色样式/CacheStorage 并整页重载。
- 组织写入口固定为 `GET/PATCH /api/admin/schools/{id}` 与 `GET/PATCH /api/admin/classes/{id}`。PATCH 只接受声明式白名单字段、非空原因和 `expected_version`；成功响应是提交后的权威资源，409 后调用方必须重新 GET 对账，不得自动重放。归档组织拒绝后续教学写入并从当前学情/进度中排除，但管理读取和历史数据继续保留。
- 管理组织编辑器先精确 GET，再把身份、状态和版本作为只读权威字段展示；元数据与归档/恢复分开确认，每次操作最多一次 PATCH。2xx 后精确 GET 对账，409 保留草稿并读取新版本；发送后出现取消、超时或网络错误时保留写锁，只有显式对账确认未应用后才解锁。
- 当前统一基线的 page registry、Router、main、Service Worker 壳层与教师三层样式/脚本使用 `20260719v75ReviewTeacherLayersP0`；代码空间入口仍为 `759r1`，未改动的 base、planets、student、admin 与未来发布上下文保持各自既有代际。`teacher-style-layer-contract.cjs` 冻结三层顺序与原级联哈希；角色资源匹配覆盖 `pages/student|teacher|admin` 下所有顶层 JS/CSS，仍为 network-only且不得进入共享 CacheStorage。
- 高基数读取必须优先使用 `/api/classes/{id}/members/page`、`/api/assignments/{id}/submissions/page`、`/api/learning-events/page` 与 `/api/code-submissions/{id}/attempts/page`。旧数组接口只允许兼容不超过 200 项；收到 `legacy_list_limit_exceeded` 后必须切换响应给出的分页 URL，不得重试旧数组端点。
- 前端认证显示不得替代后端授权；浏览器不得读取 HttpOnly Cookie、兼容 token 或持久化业务 token，也不得缓存 `/api/*`。非浏览器 Bearer 调用必须显式排除 Cookie；混合、重复或畸形凭据由后端 fail closed。
- C++/Node 静态服务不得恢复业务 API，也不得挂载仓库根目录。
- 数据库结构变化必须带 Alembic、回滚考虑、SQLite 回归和真实 MySQL 门禁。
- 目标发布证据只接受 `target-release-v2`：manifest 先冻结 target instance/origin/public probe host 与 release version/revision/同包五类制品清单路径/SHA/bundle ID；seal、51 项总闸和 Windows 服务包共用公开 DNS/标准 443 的精确 HTTPS origin 校验，IP、单标签、保留/示例域、非法 DNS label、路径或非标准端口均失败关闭。原始 evidence 数组必须精确七项且 run ID 唯一，自动 raw 必须携带执行时间，再经 `target_release_evidence seal` 固定语义，并同时接受封装时刻与总闸当前时刻的新鲜度复核。目标 topology 必须绑定外部探测引用和可解析公网 host、强制原始 API 端口不可达并逐项回读四服务 SCM；deploy smoke 必须通过单一 0047 组织治理列与 `version >= 1`；浏览器报告必须含三角色、资源隔离、陈旧版本 409 及组织归档/恢复。正式 CLI 不接受时间覆盖，不得提交真实 evidence bundle。
- Windows 目标服务不得把 DSN、审计盐或 bootstrap token 放入 XML、命令参数、系统级普通环境或报告。`windows_dpapi_secret_store.py seal` 从 stdin 接收 `ASTRA_*` JSON，使用 DPAPI LocalMachine，并在创建时给专用父目录与文件写入受保护 DACL；只有冻结的操作者 SID、SYSTEM、Administrators 和所选 LocalService/NetworkService 可访问，操作者 SID/服务账号同时绑定加密载荷与外层元数据，服务运行时不得改用“当前 SID”误判 ACL。bootstrap token 只进入 API，不进入 worker。目标浏览器 proof 只接受公开 DNS、标准 443 的同源 HTTPS、明确 `staging/production` health、干净 Git、仓库外空输出目录和 `ASTRA_ADMIN_BOOTSTRAP_TOKEN` 环境注入；成功后直接生成绑定当前 `release_revision` 的固定 `target-browser-smoke.json`，完成后仍须独立做 MySQL 权威总账及 target-release-v2 封装。
- 外部投递、问题同步和审计锚定默认关闭，启用需要独立审批与 staging 证据。
- 详细模块、接口、页面、命令和反例继续维护在 [`01-开发者手册.md`](01-开发者手册.md)；本文只提供规范入口和当前连接关系。
