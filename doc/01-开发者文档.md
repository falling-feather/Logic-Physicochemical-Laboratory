## 1. 系统全貌

星序由主站 SPA、代码空间子站、FastAPI 业务后端、数据库和静态交付服务组成。浏览器先通过 `/api/users/me` 确认服务端 Session，再启动 Router；学生、教师和管理员的导航、section 与受保护脚本按权威角色裁剪。

```text
主站 index.html / shared / pages ──┐
代码空间 codevis ──────────────────┼──> 浏览器 + HttpOnly Cookie
                                   │             │
                                   │             ▼
Node/C++ 静态服务 <────────────────┘      FastAPI backend
                                                  │
                                      SQLite 开发 / MySQL 发布
```

当前稳定基线为 V7.4.26：V7.4.13 已完成页面注册表首片，V7.4.16 已完成 88 项实验注册结构首片，V7.4.17—V7.4.18 已启用 23 项整页离开 cleanup，V7.4.19 修正 DNA/遗传模式 wrapper 真实 DOM 挂载并由 QA-005 独立通过，V7.4.20 修复首页移动端根级溢出，V7.4.21 恢复 09 号现行后端阶段追踪，V7.4.22 已完成 Cookie/Bearer 双通道 fail-closed 契约，V7.4.23 三角色 CSS/JS 资源级裁剪已通过 QA-008，V7.4.24 完成学校/班级受约束治理、Alembic 0047 与活动组织边界，V7.4.25 已把权威状态可视化、白名单编辑和归档/恢复接入管理台并关闭 R4；V7.4.26 只对 23 项 `verified:true` 实验启用精确模块级 cleanup，65 项 legacy 保持 fail closed并关闭 R4b。当前任务和版本见 [`02-项目规划.md`](02-项目规划.md)，后端执行顺序与退出门禁见 [`09-后端阶段收束小版本开发安排.md`](09-后端阶段收束小版本开发安排.md)。

## 3. 启动与验证

从仓库根目录执行：

```powershell
npm ci --ignore-scripts
node server/dev-static-server.mjs --port 8766
```

另一个终端执行：

```powershell
Set-Location backend
python -m pip install --require-hashes -r requirements.lock
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

联调入口为 `http://127.0.0.1:8766/?backendSchema=1&apiBase=http%3A%2F%2F127.0.0.1%3A8000#home`。完整环境、正常结果和失败排查见 [`README.md`](../README.md) 与 [`04-部署指南.md`](04-部署指南.md)。

提交前最低验证：

```powershell
python -m pytest backend
npm test
git diff --check
```

## 4. 扩展与维护边界

- 新增主站页面前先在 [`02-项目规划.md`](02-项目规划.md) 建立任务，再同步 `AstraPageRegistry`、DOM 导航身份、脚本/钩子、HTTP fallback、Service Worker 和契约；角色权限继续只由 `app-session.js` 掌管。
- 新增实验需同步 `CONFIG.experiments`、`AstraExperimentRegistry`、`data-module` DOM 和对应实现文件；脚本/init/cleanup 状态只在注册表登记，`ModuleSelector` 是运行入口，Router 不再维护实验清理表。
- cleanup 边界保持 65 项 `legacy-callback / verified:false`、23 项 `validated-callback / verified:true`、0 项 `missing`。`AstraExperimentRegistry.cleanupModule(subject, id)` 只执行精确 `verified:true` owner，并返回冻结报告 `unknown`、`unverified`、`owner-unavailable`、`cleaned` 或 `failed`；65 项 legacy 绝不执行模块级 callback。`openModule()` 的 A→B 与 `closeModule()` 的 B→画廊会先关闭学科 Zoom，再清理当前已验证 owner；owner/Zoom 失败在 DOM、hash 和 active state 变化前中止。成功 cleanup 删除初始化标记以允许重新 init；legacy 保留初始化标记。transition generation 会取消或失效旧资源加载、init 重试、resize、焦点和相关推荐 timer，dirty legacy 不得在同页重复 init；整页离开继续由 `cleanupPage()` 兼容清理，并通过 `skipExperimentCleanup` 防止双执行。
- V7.4.19 将 DNA/遗传的模式 wrapper 查找从错误的 `.canvas-container` 子树改为真实 `.demo-section` 范围；`bio-dna-modes`、`bio-photo-modes`、`bio-genetics-modes` 在桌面和 390×844 各三轮进入/切换/离页/重入后均为单例。候选 cleanup 合同也使用与 `index.html` 一致的 controls/Canvas 兄弟关系，不得再用失真 fake DOM 掩盖挂载失败。
- V7.4.20 要求活动首页使用 `.page.home-page.active` 恢复 `position: fixed`、动态视口高度与 `overflow: hidden`，子级 `.home-container` 使用 `height: 100%` 跟随父级 `100dvh`；这是对加载顺序中 `.page.active` 更高选择器权重的显式覆盖。首页的星空、极光和轨道允许在页面内部超出几何边界，但不得再进入 HTML/body 的根滚动宽度；`home-particle-lifecycle-contract` 同时冻结该 CSS 与版本化加载契约。
- V7.4.23 要求 `index.html`、`APP_SHELL` 与星系 HTTP fallback 均不得静态包含三角色 CSS/JS。`AstraPageRegistry` 维护页面角色与样式/脚本矩阵，`app-session.js` 仅在 `/api/users/me` 成功后加载允许样式；Router 只在角色守卫通过后加载页面脚本。三端资源由 Service Worker 使用 `cache: no-store` 的 network-only 分支处理，退出、运行中 401 与跨角色重新认证必须清理角色样式/CacheStorage 并整页重载，避免旧脚本继续留在同一 JavaScript 执行域。
- V7.4.24 的组织写入口固定为 `GET/PATCH /api/admin/schools/{id}` 与 `GET/PATCH /api/admin/classes/{id}`。PATCH 只接受声明式白名单字段、非空原因和 `expected_version`；成功响应是提交后的权威资源，409 后调用方必须重新 GET 对账，不得自动重放。学校/班级归档会拒绝后续教学写入并从无显式范围的当前学情/进度中排除，但管理读取、作业历史、提交和事件历史继续保留。
- V7.4.25 的管理组织编辑器先精确 GET，再把身份、状态和版本作为只读权威字段展示；元数据白名单与归档/恢复分开确认，用户修改输入后必须重新双确认，no-op 不写入。每次操作最多一次 PATCH；2xx 后以精确 GET 证明版本递增和字段一致，409 保留草稿并读取新版本，发送后取消/超时/网络错误保留跨路由写锁，只有显式对账确认未应用后才解锁。页面 owner/generation 保护旧请求不得清除新生命周期 busy；归档学校/班级使教师成员、成绩和作业策略入口只读，学生提交原因显示 `class_archived`。FastAPI CORS 允许凭据型 `PUT` 预检。
- 当前角色静态资源、HTTP fallback、Router、Service Worker 和缓存名称统一使用 `20260716v7426ModuleSwitchLifecycleP4`；`module-switch-lifecycle-contract.cjs` 覆盖精确 cleanup、legacy fail-closed、失败事务、generation、dirty init、Router 陈旧回调、引导焦点/Escape、相关推荐重试和整页不双清理。
- 前端认证显示不得替代后端授权；浏览器不得读取 HttpOnly Cookie、兼容 token 或持久化业务 token，也不得缓存 `/api/*`。非浏览器 Bearer 调用必须显式排除 Cookie；混合、重复或畸形凭据由后端 fail closed。
- C++/Node 静态服务不得恢复业务 API，也不得挂载仓库根目录。
- 数据库结构变化必须带 Alembic、回滚考虑、SQLite 回归和真实 MySQL 门禁。
- 外部投递、问题同步和审计锚定默认关闭，启用需要独立审批与 staging 证据。
- 详细模块、接口、页面、命令和反例继续维护在 [`01-开发者手册.md`](01-开发者手册.md)；本文只提供规范入口和当前连接关系。
