# 星序 Astra 项目指引

## 项目定位

星序 Astra 是多星系可视化学习平台，当前由三个主要星系构成：

- 工科试验室：主站核心星系，包含数学、物理、化学、算法、生物五大学科和 88 个可视化实验。
- 代码空间：`/codevis/` 独立子站，提供 JavaScript / Python / C / C++ 代码执行追踪与运行时抽象。
- 未来星系：主站内的跨学科探索星系，包含地球与宇宙、工程、数据科学、信息技术、材料、人文可视化等方向。

正式文档和可见 UI 中统一使用“工科试验室”；历史条目可保留旧称“工科实验室”。

## 当前阶段

当前主线处于 V6.5.0 后端开发准备阶段：

- 第一批后端生成页面优先选择工科试验室实验页，复用既有模块化页面和模板基础。
- 后端技术路线采用 Python + FastAPI + MySQL。
- 登录先采用简单本地账号注册与登录，不引入强身份验证或统一身份认证。
- 平台需要学校/组织层级，教师和学生都在学校内选择加入班级。
- 管理端、教师端、学生端三端都要围绕学校、班级、课程、作业和学习统计建立权限边界。
- 教师自定义页面原则上允许脚本能力，但具体脚本必须经过讨论、审核和安全边界设计。
- 代码空间运行记录、AI 助教和 OJ 作业模块放入后续二期，本阶段只预留模型和接口扩展位。
- 学生画像先采用规则统计，只按作业频次、数据量、完成率、正确率、百分比等可解释指标生成基础分析。

## 文档边界

## Git 提交规范

后续 Git 提交统一使用以下格式：

```text
V{大版本}.{中版本}.{小版本} 中文提示
```

示例：

```text
V6.5.0 文档整理收束，后端开发准备
V6.5.1 初始化 Python 后端骨架
V6.5.2 接入 MySQL 用户模型
```

要求：

- 提交消息必须以大写 `V` 开头，紧跟三段数字版本号。
- 版本号后保留一个空格，再写中文提示。
- 中文提示应说明本次提交完成的真实内容，避免空泛词。
- 不再在主线提交中使用 `feat:`、`fix:`、`docs:`、`chore:` 等未标版本号的 conventional commit 前缀。
- 不提交 `WIP`、`temp`、`checkpoint` 这类临时消息到主线。
- 如果需要记录细碎历史，优先在 feature/legacy 分支保留细节；main 分支提交应保持版本号清晰。

## 协作注意

- 不恢复已结束赛事提交材料、预检脚本、截图清单或临时展示路径。
- 新增后端功能前，先确认数据模型、权限范围、文档边界和验收方式。
- 改动 Service Worker、缓存版本、入口脚本或路由表时，必须同步版本号并做回归检查。
- 涉及教师自定义脚本、学生数据、作业记录、AI 助教或 OJ 判题时，默认按较高安全敏感度处理。
