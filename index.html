地球与宇宙科学

用太阳高度理解季节

季节主要来自地轴约 23.44° 的倾斜：地球绕太阳运动时，太阳直射纬度在南北回归线之间移动，改变各纬度的正午太阳高度和昼长。

季节、太阳高度与昼长

拖动日期和纬度，观察太阳赤纬、正午太阳高度、理论昼长和本半球季节倾向如何同步变化。

Axial Tilt

这是近似学习模型，不处理大气折射、地形遮挡、云量、时区和地方真太阳时差异。

How to Read

把季节图读成四个问题

季节、太阳高度和昼长是同一套几何关系的不同投影。先看地轴指向，再看直射纬度、观察纬度和太阳在天空中的路径。

01

地轴决定哪边更直接

地轴倾斜使一年中不同半球轮流获得更直接的阳光。北半球夏季不是因为地球离太阳更近，而是北半球朝向太阳更多。

02

赤纬指出直射纬度

太阳赤纬可理解为直射点相对赤道的纬度。它在南北回归线之间往返，决定同一天不同纬度的正午太阳高度。

03

纬度改变太阳路径

同一天，低纬地区太阳高度通常更高；高纬地区日出日落角度更浅，昼长变化也更明显。

04

近似模型不能替代实测

本页不处理大气折射、天气、地形遮挡、时区和地方真太阳时。实际日出日落会因这些条件偏离理论值。

Data & AI

数据科学与 AI

从特征、标签、损失函数和参数训练开始，理解一个模型怎样把散点数据转化为可解释的预测线。

从散点到模型

线性回归把一个或多个特征映射到预测值。入门时先看单特征模型 ? = b + wx：点到预测线的竖直距离是残差，普通最小二乘会寻找让残差平方和最小的直线。

输出 预测 ?
目标 降低残差平方和
方法 最小二乘与梯度下降

先把模型读成一条学习链

线性回归的关键不只是“画一条线”。它把输入特征、模型参数、预测误差和适用边界连在一起；先读懂这条链，再去调节实验台上的斜率和截距。

01 · Data

特征与标签

特征 x 是模型已知的输入，标签 y 是观测到的结果。预测值 ? 来自模型，不一定等于真实观测值 y。

02 · Model

权重与偏置

在 ? = b + wx 中，w 对应直线斜率，b 对应截距或偏置；训练过程调整这些参数，让预测更贴近数据。

03 · Loss

残差与平方损失

残差是 y - ?。把残差平方后求和得到 SSE，取平均得到 MSE；平方会放大较大的误差。

04 · Boundary

范围与解释边界

残差图应尽量像随机波动；若出现弯曲、扇形或孤立大点，就要警惕非线性、异常值或样本范围外推。

Regression Model

线性回归与损失函数

调节斜率和截距，观察残差与平均平方损失如何变化；也可以一键显示最小二乘线，或用梯度下降逐步靠近它。

Least Squares

线性模型适合近似直线趋势；散点图、残差图、样本范围和异常点同样重要。相关关系不自动说明因果关系。

How to Read

把一条回归线读成四个问题

线性回归不是只找一条看起来合适的直线。先确认变量含义，再看残差、损失和预测范围，才能判断模型能解释什么、不能解释什么。

01

变量代表什么

x 是特征，y 是标签，? 是模型预测。斜率表示 x 每增加 1 个单位时，预测值平均改变多少；解释时必须回到具体场景。

02

残差有没有模式

残差是数据点到预测线的竖直差。若残差随 x 呈弯曲、扇形或孤立大点，直线模型可能遗漏了非线性关系或异常样本。

03

损失怎样被压低

最小二乘线让残差平方和尽量小，MSE 是平方误差的平均值。因为平方会放大大误差，异常点会明显拉动直线位置。

04

预测能走多远

在样本 x 范围内预测通常更稳妥；向外延伸需要额外证据。相关关系不自动说明因果关系，R2 也不能替代背景解释。

信息技术基础

DNS

名字到地址

域名系统把人可读名称组织成分布式层级，并通过解析器向名称服务器查询记录；缓存会让下一次查询更快。

HTTP/2

语义到帧

HTTP/2 把请求和响应映射成二进制帧，并用流在同一连接上交错传输多个交换，减少应用层排队等待。

TCP

可靠字节流

TCP 为应用提供可靠、有序的字节流；序号、校验和、确认与重传共同处理丢失和错误。

IPv6

寻址与跳数

IPv6 包携带源地址、目的地址、Next Header 与 Hop Limit；每经过转发节点，Hop Limit 会递减。

Packet Journey

网络分层与数据包旅程

选择一次网络操作，调节应用数据大小和路径跳数，观察应用数据如何依次进入 TCP 段、IPv6 包和链路帧。

DNS · HTTP/2 · TCP · IPv6

这是分层学习模型：TCP 头部按最小 20 B、IPv6 固定头部按 40 B、单段上限按 1200 B 近似处理；真实网络还会受到 MTU、TLS、HTTP 版本、拥塞控制、压缩和链路类型影响。

How to Read

把一次请求拆成四个问题

同一次访问会同时出现名称、连接、寻址和链路传递。先问每一层负责回答什么，再判断图中的字节和跳数属于哪一层的近似。

01

DNS 回答“去哪里”

域名是人可读的名字；浏览器或系统缓存没有答案时，会向 DNS 服务器查询对应 IP。DNS 负责找到地址，不负责传输网页数据本身。

02

TCP 回答“怎样可靠交付”

TCP 面向字节流，用序号、确认、校验和与重传支持可靠、有序传输。MSS 与路径 MTU 会影响每个段能承载多少数据。

03

IP 回答“下一跳走哪条路”

IPv6 包携带源地址、目的地址、Next Header 和 Hop Limit。路由器按目标地址转发，Hop Limit 会随每一跳递减。

04

链路回答“这一跳怎么送”

每一跳会在本地链路重新封装成帧。页面的总经过量是观察链路传递的教学估算，不是抓包工具里的完整开销。

01

整体先满足平衡

把整座桥当作刚体时，竖向力之和和任一点力矩之和都应为零。荷载位置改变时，左右支座反力会随力臂一起改变。

02

节点法把每个铰接点当成受力粒子，分别列出 ΣFx = 0 与 ΣFy = 0。已知力会沿相邻杆件传到下一个节点。

03

符号决定拉还是压

常见做法先假定未知杆力为受拉；计算结果若为负，表示实际方向相反，也就是受压。本页用青色表示受拉、琥珀色表示受压。

真实设计还要继续检算

理想桁架忽略节点刚度、杆件自重、屈曲、疲劳和组合荷载。这里帮助建立受力直觉，不代替截面选择和工程规范验算。

05

零力杆只对当前荷载成立

某些杆在一个荷载工况下可能近似不传力，但在车辆移动、风载或温度作用下可能重新参与受力，因此不能简单删除。
